# Settings and themes

Part of CLAUDE.md, moved out to keep every session's context small. Read it before working in this area; keep it current.

- **Settings** (`KisSettingsRegistry` + `KisStudioSettings`):
  - The registry is the single source of truth for every setting: id, default, read/write, flags (`Restart`, `Machine`, `Fork`, `NewViews`), tooltips in `explanations()`. It keeps the history behind settings undo (`KisSettingsUndo`), ordered against each document's steps by one journal of marks, not clocks (`nextStamp`; each document's stack is watched as steps are pushed or redone, `watch`), so redoing keeps the order and other images' steps never count; with no image open, Ctrl+Z takes back settings alone. Writes of one setting merge into one step only within one gesture (a press, a turn of the wheel, typing in one field), never by time across separate acts. Write settings through it, not `KConfigGroup`, or they fall out of undo. A write made inside another's `written` hook joins that step; `setValues()` makes several writes one step. Krita's own config-changed broadcast (which resets the canvas, reallocates its buffers and pushes autosave back) goes out only for settings Krita reads: a Fork setting applied by its own listeners carries `OwnNotice`; one applied through `configChanged` must not. The broadcast also ends what is open on the canvas (an effect being tuned was applied when its own "keep editable" toggle wrote `StudioEffectsEditable` without `OwnNotice`). `Fork` itself only describes a setting; nothing reads it. A drag of a setting the theme holds keeps one before and after per id in its step.
  - `forgetRetired()` is a versioned one-time migration clearing removed settings: bump its version, keep it idempotent. A setting no longer shown must still be read correctly or be migrated; deleting a key upstream still reads is a bug.
  - Arranged lists are settings too (`itemList`: the tool rail, the bar and pill buttons, the panel buttons, and what each picker lists first), so Ctrl+Z takes them back; their owners apply an undo from `valueChanged`. Pickers write their lists with `KisSettingsRegistry::writeList`, which makes a registered list one undo step.
  - Where the panels and bars are is one setting, `StudioLayoutArrangement` (every `StudioLayout*` key but the Studio switch and the classic state, the zoom pill's place and the pinned panels hidden by their button, `StudioLayoutHiddenPanels`, among them, as JSON: `KisStudioLayout::arrangementNow`; a gesture that also changes the panel buttons writes them in the same step). Each gesture that arranges (a move, a resize, a fold, a pin, a join or split, a tuck) ends with `commitArrangement()`, which makes it one step once the event is done; an undo writes the keys back and `reloadArrangement()` arranges every window again from them. Writes the layout makes by itself between gestures go into the next step.
  - Frequent non-setting writes (slot brushes, panel places, Find usage) go through `KisSettingsRegistry::writeLater`; a `KisConfig(false)` rewrites the whole kritarc; a raw `KConfigGroup::writeEntry` needs `scheduleSync()` after it or a crash loses it. Krita's own immediate writes stay (its crash detection relies on them).
  - Sections: Appearance, Canvas, Pen, Keys, Tools, Files, System (speed, screens, proofing, resource folder, updates), Help (All commands, Gestures and the help menu's commands as buttons, read from the window when the card is built). A card holds one subject; a card with a few related things names them with `Builder::part` (Cursors: Brush, Eraser, Color sampler). Cards folded into others keep working by their old ids through `currentCardId` (Quick, user sections, links): add a line there when a card moves or merges. Merge only what is one subject to the artist: two things that merely look alike (the checkerboard and the pixel grid) made a card the owner called stupid. Left out of the panel on purpose, at Krita's values (still read, still in Find's commands where Krita has them): instant preview, processor threads, frames rendered at once, merging strokes in undo, faster color conversion, channels in color.
  - The panel is cards (`Builder`: `toggle`, `number`, `choice`, `color`, `row`, `part`…), user sections, Quick, a Changed filter, search and an Undo for changes since it opened; a card's menu is its right click. A setting needing a restart gets a quiet refresh mark and a Restart button; never write "After a restart".
  - Back up / Restore (Settings ⋯; `KisSettingsTransfer::backUp`, `planRestore`, `restoreResources`): one zip (`KoStore`) of settings.json (`exportSettings`, arrangement and shortcuts included), tags.json (`readKritaTags` on a copy of the own database), files.txt and the resource folders' files. Restore copies only resources not here, tags them (the rest at the next start through the pending tags), then shows the settings as a plan; a settings .json restores too. Back up each day to a chosen folder (`StudioBackupFolder`, `backUpDaily` 20 s after start, written on a thread beside the target then renamed, the newest 7 kept).
  - `KisSettingsTransfer`: Take Krita's settings / brushes (copies; files here are kept; Krita's files are never written). Taking brushes also takes what only Krita's resource database holds (read from a copy of its `resourcecache.sqlite`): its tags and what they tag (resources matched by md5, else file and storage), resources it hides, bundles on or off; tags are only added, never deleted. What waits for files just copied goes to `krita-tags.json` and is done at the next start (`takePendingKritaTags`). Export carries the user's arrangement too (`arrangedKeys` prefixes, `arrangedGroups`, kritashortcutsrc); import backs up to `.before-import-<time>`. Add new kinds of arrangement to those lists or export loses them.
- **Theme** (`KisStudioTheme`): a theme is a few params (lightness, tint, tint amount, accent) turned into a generated `.colors` scheme ("Skissa"), plus glass, the glow around the image and the UI font (`held()`). Themes are one list (`[StudioThemes] List` JSON and `Current`, registry settings, so changes are undoable); the shipped ones (Dark, Darker, Night, Moss, Light, Paper, Sky, Blossom) are editable like the user's, with Reset and Restore deleted. Editing a held setting writes into the current theme (`remember`). The picker (`ThemePicker` in `KisStudioSettings.cpp`): dark rows above light, four across; + copies the current one; double-click renames, right-click resets or deletes. New profiles start Light ("Skissa Light", lightness 0.97); a profile from before that never set the look keeps Dark, pinned once in `remake()` (`[StudioThemes] LightDefault`). First run keeps the look in use (`settle()`, "Mine" if no shipped theme matches); `remake()` renames old placeholder names. Writing a param only marks the scheme: it is written, and the palette reloaded once, on the 40 ms tick.
- Defaults taken from the owner's own installed profile where they had tuned them (November 2026): weighted smoothing at 85 with the end at the pen, the selection actions bar off (the bar's Deselect and Invert show instead), 35 px layer thumbnails, glass blur 4, opacity 0.7 and vibrancy 0.7, the color panel's hue strip, and Skissa's Flow as the first brush.
