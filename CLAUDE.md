# Skissa: how we build it

This is the working guide for this fork. Read it before changing anything; it explains what we value, how the main systems fit together and how to work with the owner. **It is a living document: when you learn something that a future agent needs (a principle the owner states, a mistake worth not repeating, a system you added), add it here in the right section, briefly, and remove what has become false.**

## What this is

Skissa (Swedish: "to sketch") is a personal fork of [Krita](https://invent.kde.org/graphics/krita) (upstream: KDE). Branch `main`, pushed to the `skissa` remote's `main`. The owner is a digital artist who paints in Krita daily and wants it to feel as obvious and visual as the tablet apps (Procreate-like) without losing Krita's power. The fork rebuilds the interface ("Studio"); the painting engine, file formats and resources stay Krita's.

The owner works fast and reviews results afterwards. They mostly talk about how things look and feel, not about code.

## How to work with the owner

- **Automate; don't ask what you can decide.** Build, install, relaunch, test and commit without checking in. Ask only for decisions that are really theirs (design direction they reserved, outward-facing actions like pushing or publishing).
- **"Give me suggestions" means text only.** Don't implement suggestions until they say "implement", "do it", or pick numbers. When they pick, do exactly those.
- **Finish every task in a message**, including ones sent mid-turn. Keep a list.
- **Verify visually.** Launch the dev build and capture the window (see Dev workflow) before saying a UI change works. Say plainly what you could not verify.
- **Report like a person:** what changed, what they'll notice, what's left. Short.
- When the owner says something feels wrong, believe it and find the cause; don't argue from the code.
- Before changing a look the owner has opinions on (glass, glow), get a reference image of what they want; don't iterate on numbers blind.

## Design principles

These come from the owner's feedback over many sessions. They decide most questions.

1. **The canvas is the product.** Chrome is a cost. Everything else appears where and when it's needed and gets out of the way.
2. **Needing explanation is a design problem.** Before adding a hint or tooltip, make the control self-evident: a picture, a live preview, direct manipulation, a better default, or removing the option.
3. **No grey helper text. Ever.** No info icons, no descriptions under settings, no "click to…" labels. A short tooltip is the fallback. Grey (secondary ink) is for quiet *values or state*, never for instructions.
4. **Sentence case.** "Open recent", not "Open Recent". Krita's Title Case text is shown in sentence case in English (`KisSentenceCase`; names and acronyms keep their capitals; translations untouched): menu commands (`KisStudioLayout::tidyCommand`, which also keeps classic-only items hidden), form captions without their colon (`KisModernStyle::polish`), option names (`KisPaintOpOption::label`), widget tooltips (`KisStudioTips`). Items the user named (files, layers, brushes) never go through it.
5. **Shortest clear text.** "Layer 5", not "Paint Layer 5". Drop type names, restated context and "Click to". Most controls need no tooltip: if the name says it, leave it out. When one is needed, it's one line an artist would say, telling what the name can't ("Huge brushes paint slowly", "Nearest is best for pixel art"): no restating the name, no "X, but Y" or "…, so …", no "e.g.". A short name before ": " shows in bold above the rest (`leadOf`). A button whose name says what it does gets just the name.
6. **Direct manipulation over forms.** Drag a value on its own label or row. Handles on the canvas instead of number fields. Typing is a double-click away, in place, no box (`widgets/KisStudioInlineEdit`). **Right-click resets a value to its default.** Shift drags finer. The wheel over a value changes it too (custom ones: `KisModernStyle::setWheelValue`); a turn of the wheel belongs to the widget it started over (`WheelLatch`), so a page scrolled past sliders keeps scrolling and never changes them.
7. **Show, don't name.** Live previews on the real image (effects on canvas, blend modes as thumbnails of the actual picture, brush tooltips with strokes), curves as little drawings, themes as swatches.
8. **Fewer options, better defaults.** Remove settings nobody should need. Merge duplicates. Put an option where its subject is (the eraser's own size on the Size page) and also in Settings so it can be found.
9. **Organized by intent, found by search.** Group by what the artist wants ("Blur", "Darken"), not by implementation. Everything is reachable with Find (Ctrl+K), including words from other apps.
10. **Perceptual controls.** Brush size moves by ratios (log); opacity stays linear.
11. **Stable places, personal content.** Primary controls don't move. Customizing uses the same gestures as using (drag, right-click) and always has a reset.
12. **One undo.** Ctrl+Z also undoes settings changes (and rail and bar changes), interleaved with document steps by time.
13. **Stay Krita underneath.** Files and presets the fork writes must open in upstream Krita and the other way round. Never change a preset just by loading it. Keep upstream code paths intact so merges stay easy.

## Look and feel

All tokens live in `libs/widgetutils/KisModernStyle.h`. Use them; don't invent numbers.

- **Spacing:** `hairline` 2, `space1` 4, `space2` 8, `space3` 12, `space4` 16. Nothing else.
- **Corners:** squircles everywhere (`KisModernStyle::squircle`). Radii: `cornerRadius` 5 (controls), `tileRadius` 8, `cardRadius` 10, `panelRadius` 14. Checkboxes, swatches, switches and segmented controls are squircles (`fullSquircleRadius` for checkboxes). Radio buttons stay circles.
- **Motion:** one curve, an exponential ease-out (`motionCurve()`), and three durations: `enterDuration` 180 ms, `exitDuration` 120 ms, `changeDuration` 160 ms. Things that move glide, they don't jump.
- **Fields:** a text field is a soft rounded fill; focused, a little lighter with a soft edge, never a bright accent ring.
- **Ink:** text in the palette's text color; quiet values in `secondaryInk()`; fills and tracks as text color at low alpha (works on any theme and on glass). The accent is optional (themes can have none).
- **Selected rows:** use `KisModernStyle::selectedRow()` / `selectedRowInk()`, never a mix toward `QPalette::Highlight`: a theme without an accent has a gray Highlight made for checks and slider fills (dark on light themes), which made selected rows a heavy mid-gray with white text.
- **Glass:** panels, popups and dialogs are frosted glass over the canvas. See Glass below before touching any panel painting.
- **Icons:** `krita/pics/svg/{dark,light}_studio_*.svg`, generated by `krita/pics/svg/make_studio_icons.py` (24 px grid, round strokes; a switch that is on is drawn solid). The app icon is a bare pencil S (white with a soft shadow on dark, ink on light; Krita names icons by their own color, so `dark_krita-branding` is the ink one). The window icon follows Windows' light/dark setting live (`taskbarIcon()` in `KisApplication`); the .exe gets the white S with a stronger shadow at small sizes. Every icon file (file icons, macOS, Android, Windows Store tiles) comes from `krita/pics/branding/make_icon.py`; the splash wordmark is `krita/data/splash/banner.svg`.

## Main systems

A map of where things are. Files are in `libs/ui/` unless noted.

- **Studio layout** (`KisStudioLayout`): the whole shell. Left rail (tools, color chip), right rail (panels as flyouts that pin), top bar = the current tool's context (tool chip with the brush name, the tool's options, size/opacity, brush and blend mode), then its buttons (`KisStudioBarButtons`, `StudioBarItems`: symmetry, shapes, eraser, alpha lock, reload by default; any command can be added). Canvas-only mode brings the bars back while the pointer is at a canvas edge (`peek`). The classic layout is the `view_studio_layout` toggle.
  - Placement: the rail, the top bar and each panel group move by their grip (a tap tucks them away). The rail, the top bar and the zoom pill glide where they go (`KisStudioGlide`: at once while hidden, just shown, after a resize and where the pointer takes them; a catch or making way glides), as the groups do. Places are kept as shares of the room they can move in (`shareOf`, `StudioLayout*Spot` = "across,down,height", `m_refHeight`), catching on edges, corners and the middle (20 px, the middle 10; more catches too eagerly). The room is taken as if the window filled its screen (`roomGrowth`, not from the window's state, which Qt updates after the resize), so a smaller window keeps everything at its distance from the nearer edge: plain shares crept toward the edges and pushed groups into each other. A group keeps its top as it grows or folds (against the bottom, its bottom). A group against its edge is docked (the canvas makes room), elsewhere it floats. Groups keep off the rail (`railRectProperty`), the top bar and window buttons (`barRects`) and each other: an overlapping group moves to the nearest place clear of all of them at once (`clearOfOthers`, `settledCount`; the one moved last makes way, even while dragged) and glides there (`glideTo`); the owner wants to see panels move, not jump. The top bar at the top or bottom pushes the view (`studioCanvasBottomInset`); the S window handle stays top left and the rail keeps its gap under it (`handleBottomProperty`).
  - Lanes: a group is one glass pill of lanes side by side, each a stack of panels (`StudioLayoutPanelLanes`, widths in `<width key>Lanes`). A group dropped by another's side joins it as lanes; a single lane dropped at a lane's top or bottom joins that stack (`joinAt`, `joinGroups`). The line between lanes resizes on drag and splits on click (`LaneDivider`, `separateLanes`); a tap between stacked panels splits off those below (`separateBelow`). Joined groups as separate pills kept in step were tried and broke tucking and moving panels: one widget can't come apart. A grip tap folds the group's panels (`foldGroup`); a group's only panel has no title bar unless folded.
- **Panel columns** (`KisStudioPanelColumn`, `PanelStack` in `KisStudioLayout.cpp`): a panel opened from its button and not pinned is a flyout, closed by a press elsewhere in the interface, its button or Escape, but not by painting (`isCanvas`: the owner paints with panels open). First start pins Color, Brushes and Layers: Color and Brushes as a group at the bottom left beside the rail, Layers with the panel buttons (the owner's own layout, mostly). Group 0 is the column with the panel buttons, 1 the one across (`StudioLayoutFarPanels`), 2+ floating groups made by dropping a panel's grip on the canvas (`newPanelGroup`, `StudioLayoutPanelGroups`, `StudioLayoutPanelGroup<n>Spot/Width/Side`); an empty group goes. A scrolling panel is fitted to its contents once (160–360 px, `settled`) and keeps that height, so a growing list scrolls; the line under each panel resizes it (`StudioLayoutPanelSizes`; right-click fits it again). Resource lists stay lists (`keepUpright`). A resource's right click toggles tags in place and adds new ones (`resourcewidgets/KisResourceTagMenu`); over a list, the tag chooser (`KisTagChooserWidget`) and a magnifier that opens into search (`KisTagFilterWidget`).
- **Zoom pill** (`KisStudioCanvasHud`): zoom (click: 100%, from 100% to fit), value view, mirror, rotation and the modes that are on. It goes anywhere free on the canvas by a drag (`StudioLayoutViewPillSpot`, `KisStudioLayout::spotShare`), keeping off bars and groups (`studioTarget`). It holds its own `KisStudioBarButtons` (`StudioViewPillItems`, none by default; buttons drag between it and the top bar); its right click adds buttons or hides it (`StudioViewPill`, in Settings' Zoom card).
- **Start page** (`KisStudioStartPage`): with no image open the Studio shows its own page in place of Krita's welcome page. Over the last image, blurred: new-image tiles drawn to one scale (last size, screen, square, A4, 4K, portrait, clipboard), Custom, Open, then the last image large (Continue) and the others under Today, This week and Earlier (right-click: Forget), plus the images open now (unsaved too). Typing filters, arrows and Enter pick, dropped files open. Pictures are read on two threads from the files (`Pictures`; a .kra's merged image) and kept scaled on disk (`start-pictures` in the config folder, the 40 used last, JPEG when opaque), so a large .kra isn't decoded at every start. Footer: three quiet links (`FootLink`: Support Krita, Skissa, Report a problem), never a banner.
  - Custom (`CustomImage`): the sheet pulled by its corner among other sizes' outlines (`SizeStage`, catching lightly: 6 px on sizes, 4 px on ratios; Shift free; catching from far felt clumsy, none made aiming hard), numbers in px/cm/mm/in (`SizeNumbers`), shape chips that hold and size chips by the long side (`NewImage::steps`), resolution (`roundDpi`), color rows, paper colors, Make. Every new image has one layer; the owner wants no controls past those and no Krita dialog glued on.
  - Home: a click on the S handle (`WindowHandle`: drag moves the window, double click maximizes) or Find's Home shows it over open images (`KisStudioLayout::showHome`); Esc or the S again goes back.
- **Tools** (`KisStudioToolRail`, `KisStudioToolStrip`): 34 tools in 9 slots (Paint, Blend, Erase, Select, Transform, Fill, Shape, Text, Guides; Blend and Erase are the brush tool too, `toolSlots()`). Slots remember their variant; the brush in use decides whether Paint or Blend is lit. The rail's items (`StudioRailItems`: slots, single tools, spaces, Effects, and brushes pinned by dragging them from a brush list, which paint with their own size unless in `StudioRailItemsSharedSize`) are edited with undo. Inline tool options in the strip are Krita's option widgets found by object name (or by the `"id"` property inside `KisOptionCollectionWidget`, `withId`) and mirrored: selection modes with Grow and Soft (`KisStudioSelectionAdjust`; Soft is a real gaussian, made by three running-sum box blurs on all threads: any width costs the same, where Krita's convolution went through a whole-area FFT), Move's layer choice, Crop's shapes, the fill's threshold, shape fill and outline, gradient shapes, the color sampler's source and size, the magic wand's and similar color's threshold (a drag makes the last click's selection again as it goes: `KisRedoLast` takes back that click's step with `setIndex` while it is the last one done and runs the click again, one at a time; the Fill tool's settings and the color drop's panel redo the last fill the same way), the text tool's font (written in itself, opening `KisStudioFontPicker`, set through the canvas's text property data). Connections to option widgets need a context that dies with the strip's buttons.
  - Guides (`addGuides`, `plugins/assistants/Assistants`): Krita's assistant types as four kinds (Line, Perspective, Ellipse, Curve), each remembering how it was last used (`[StudioGuides]`). Snap, Lock, Duplicate and Delete are on a guide's right click (`KisAssistantToolMenu.cc`). A brush tool's bar shows a magnet while the image has guides. Captures don't show guides: test through what they change.
- **Picking layers** (`input/kis_select_layer_action`): every click picks, on release, the layer that shows most within about 3 screen px of the pointer (its alpha × opacity × what the layers above let through; within 1/255 the upper one wins), so a faint haze on top doesn't take every click and a thin line is easy to hit; clicking again there (within 8 px and 4 s), or on the active one, picks the next in that order; an 8 px drag moves the pressed-on layer. The hover pill (`KisLayerHover`) names the same layer, in the accent or, without one, the text color (`KisModernStyle::hasAccent`).
- **Export** (`KisStudioExport`, opened by Krita's export action while the Studio is on): PNG, JPEG and WebP as a busy part of the image shown at 2× as each would save it, each with the size of its file (the whole image encoded on a thread with Qt's writers, close to Krita's), Quality for the lossy ones, then only where. The settings go to Krita's filter with `skissaChosen`, which `KisImportExportManager::askUserAboutExportConfiguration` takes as already asked. Other formats… runs Krita's export.
- **Make brush** (`KisStudioMakeBrush`): the selection's visible pixels become a picture tip (paper color made see-through, cropped, ≤1024 px; gray ones a mask, colored ones a stamp), saved in the brush panel's tag, picked, the quick editor opened on it.
- **Mixing** (`libs/pigment/compositeops/KoCompositeOpMix.h`, `KisStudioMixing`): a brush's paint mixes as Krita does (RGB), evenly (OKLab) or as pigment (a Mixbox-like model fitted in `C:\code\krita-deps\pigments-lab`), the brush setting `SkissaMixing`, chosen as three tiles in the quick editor's Color tab and in the brush sheet. Ops `skissa_mix_{oklab,pigment}_{over,copy}`, converting through the image's profile to linear (`KoCompositeOpInLinear`, keeping channel locks; 8-bit sRGB by tables, only the span a dab's mask covers: LCMS took two thirds of the time); the stroke uses them for Normal (`KisResourcesSnapshot`, smudging's `mixedCompositeOp`). Only the pigment over op is registered, as the layer blend mode Pigment (`KoMixing::layerMode`); brush blend lists leave it out (`KisCompositeOpComboBox::setForBrush`, `isLayerOnly`). Upstream Krita ignores the setting and reads the mode as Normal.
- **OKLCH blend modes** (`compositeops/KoCompositeOpOklch.h`): Hue, Chroma, Color and Lightness in OKLCH (`skissa_oklch_*`, `KoOklch::addTo`), out-of-gamut results giving up chroma. Registered with the mixing ops (`KoCompositeOpMix::all`). Upstream reads them as Normal.
- **Glow blends** (`compositeops/KoCompositeOpGlow.h`): Clip Studio's light modes, where the paint is scaled by its coverage and used as light, so soft, see-through paint glows fully. Add (glow) is Krita's own "Luminosity/Shine (SAI)" renamed in the registry (`KoGlow::addTo`; files stay Krita's); Glow dodge (`skissa_glow_dodge`, `cfGlowDodge`: under / (1 − paint × alpha), the paint as it is where nothing is under it) is added beside the SAI op in `KoCompositeOps.h`. Upstream reads Glow dodge as Normal. A picker's items added after users saved groups go once into their own category's group (`Source::addedLater`, remembered in `<groupsKey>Placed`, so taking one out again sticks).
- **Find** (`KisStudioFind`): one index of keyed items (`tool:…`, `effect:…`, `brush:…`, settings, commands with their classic menu path), ranked by prefix, word start, initials, all-words, then fuzzy, plus frecency and aliases from other apps. Uses fade with a time constant of 30 days (`Usage::countNow`, stored as the faded count at the last use), so what is used now outranks what was used often long ago. Right-click or long-press any button opens its card (`KisStudioItemCard`: shortcut as a re-recordable key cap, variants, pin/remove); a button with a card of its own sets `ownContextMenu`.
- **Settings** (`KisSettingsRegistry` + `KisStudioSettings`):
  - The registry is the single source of truth for every setting: id, default, read/write, flags (`Restart`, `Machine`, `Fork`, `NewViews`), tooltips in `explanations()`. It keeps the history behind settings undo (`KisSettingsUndo`). Write settings through it, not `KConfigGroup`, or they fall out of undo. A write made inside another's `written` hook joins that step; `setValues()` makes several writes one step. Krita's own config-changed broadcast (which resets the canvas, reallocates its buffers and pushes autosave back) goes out only for settings Krita reads: a Fork setting applied by its own listeners carries `OwnNotice`; one applied through `configChanged` must not. `Fork` itself only describes a setting; nothing reads it. A drag of a setting the theme holds keeps one before and after per id in its step.
  - `forgetRetired()` is a versioned one-time migration clearing removed settings: bump its version, keep it idempotent. A setting no longer shown must still be read correctly or be migrated; deleting a key upstream still reads is a bug.
  - Arranged lists are settings too (`itemList`: the tool rail, the bar and pill buttons, the panel buttons, and what each picker lists first), so Ctrl+Z takes them back; their owners apply an undo from `valueChanged`. Pickers write their lists with `KisSettingsRegistry::writeList`, which makes a registered list one undo step.
  - Where the panels and bars are is one setting, `StudioLayoutArrangement` (every `StudioLayout*` key but the Studio switch, the classic state, the panel buttons and the zoom pill, as JSON: `KisStudioLayout::arrangementNow`). Each gesture that arranges (a move, a resize, a fold, a pin, a join or split, a tuck) ends with `commitArrangement()`, which makes it one step once the event is done; an undo writes the keys back and `reloadArrangement()` arranges every window again from them. Writes the layout makes by itself between gestures go into the next step.
  - Frequent non-setting writes (slot brushes, panel places, Find usage) go through `KisSettingsRegistry::writeLater`; a `KisConfig(false)` rewrites the whole kritarc; a raw `KConfigGroup::writeEntry` needs `scheduleSync()` after it or a crash loses it. Krita's own immediate writes stay (its crash detection relies on them).
  - The panel is cards (`Builder`: `toggle`, `number`, `choice`, `color`, `row`…), user sections, Quick, a Changed filter, search and an Undo for changes since it opened; a card's menu is its right click. A setting needing a restart gets a quiet refresh mark and a Restart button; never write "After a restart".
  - `KisSettingsTransfer`: Take Krita's settings / brushes (copies; files here are kept; Krita's files are never written). Taking brushes also takes what only Krita's resource database holds (read from a copy of its `resourcecache.sqlite`): its tags and what they tag (resources matched by md5, else file and storage), resources it hides, bundles on or off; tags are only added, never deleted. What waits for files just copied goes to `krita-tags.json` and is done at the next start (`takePendingKritaTags`). Export carries the user's arrangement too (`arrangedKeys` prefixes, `arrangedGroups`, kritashortcutsrc); import backs up to `.before-import-<time>`. Add new kinds of arrangement to those lists or export loses them.
- **Theme** (`KisStudioTheme`): a theme is a few params (lightness, tint, tint amount, accent) turned into a generated `.colors` scheme ("Skissa"), plus glass, the glow around the image and the UI font (`held()`). Themes are one list (`[StudioThemes] List` JSON and `Current`, registry settings, so changes are undoable); the shipped ones (Dark, Darker, Night, Moss, Light, Paper, Sky, Blossom) are editable like the user's, with Reset and Restore deleted. Editing a held setting writes into the current theme (`remember`). The picker (`ThemePicker` in `KisStudioSettings.cpp`): dark rows above light, four across; + copies the current one; double-click renames, right-click resets or deletes. First run keeps the look in use (`settle()`, "Mine" if no shipped theme matches); `remake()` renames old placeholder names. Writing a param only marks the scheme: it is written, and the palette reloaded once, on the 40 ms tick.
- **Glass** (`KisStudioGlass`, `opengl/KisOpenGLGlass`):
  - Panels over the canvas are painted *by the canvas* (GL blur/refraction behind them); the widget paints only its content. A panel is see-through only after a canvas frame drew all of it (`Panels::drewOver`), solid until then.
  - The look (`glassSource`, after preyneyv's Shadertoy wfGXzh of Apple's Liquid Glass): refraction in a 20 px band at the rim, frost following the glass's thickness (`frostAt`, octave copies mixed with B-spline weights; small textures read with a cubic B-spline, `softAt`), and a one-pixel hairline of concentrated light at the edge (Rim light, `StudioGlassRimLight`). The owner wants the edge thin, sharp and vibrant. Tried and rejected: a mirrored reflection band (big and blurry), light added from the image beside the rim (counted twice), refraction across the whole panel (magnifies, loses the edge), a full rebuild as one refraction-and-frost model (every version worse). Never blend a sharp image straight into a heavily blurred one (a double image). Red and blue taken from the sharp image in the rim band fade in with the bend (`sharp`); taken whole up to the band's inner side, they ended in a visible seam where a strong edge crossed it. There are no refraction or clarity settings. Dispersion is physical: each color's bend scaled by its n − 1 for a glass of Abbe number 20 (`ior`, blue furthest), so the colors part most at the very edge; window glass (55) is too little to see.
  - Vibrancy and Grain, both in Oklab and on the CPU glass alike (`vivid()`, `grainAt`, `tinted()`): vibrancy raises chroma by a gain that falls toward sRGB's most vivid chroma (0.32) and fades near black and white (default 50%; 200% reads neon); grain is plain random noise per pixel in Oklab lightness (a sum of three hashes, close to a gaussian), as strong on dark glass as on light, fixed to the panel (default 30%, the owner's choice; it also hides banding in wide blurs). Its slight random clumping reads like paper, which the owner likes; a spectrum-shaped (FFT, blue-noise-like) grain faded toward black and white was tried and read as too even and too faint on dark glass. Tried and left out: Text contrast (what is behind taken toward the panel's lightness: at strength it read as a solid panel washed in color, and Opacity already adapts to the brightness behind) and Distortion (bumps shifting what the glass reads, from pixel-sized frost to ripples, lit from the top left): the owner preferred the grain alone, which reads somewhat like paper.
  - Blur goes to 400% (`KisStudioGlass::maxBlur`); past 200% the canvas is downsampled further (`factor` in `KisOpenGLGlass::render`) so the widest kernel stays within its 64 taps.
  - Opacity (default 85%) is one curve each over dark and bright canvas (`tintOverDark`, `tintOverBright`). Each panel's blur is redone only where the canvas redrew (`canvasRedrawn()`).
  - The glow around the image is remade only for changes near its edge; its strength is Glow's Strength (`StudioSurroundGlow`, held by the theme); it never falls below a dim least lightness (`ambientBacklight`), raised in the glow's own hue (raised as gray, a dark blue image glowed gray), and bright light is compressed (`ambientKnee`; the owner found 0.5/0.25 overwhelming on a white page, it is 0.4/0.15). Around the image set to black keeps the chosen color apart (`StudioSurroundColor`).
  - Translucent popup windows must never have fully clear pixels (Windows passes the pointer through them and hides the cursor): the style fills them with alpha 1. Captures re-render popups, so they never show first-frame glass bugs. Tooltips are not canvas glass: they paint a solid rounded panel themselves (`paintTooltip`); as canvas glass they cut hard-edged holes into the panel under them and left a frame of glass behind on hiding. Synthetic moves can't raise tooltips (Qt shows them at the real cursor): reason about them from the code.
  - Create framebuffers through `KisOpenGLGlass`'s `texture()`, which keeps the binding: a `QOpenGLFramebufferObject` made mid-frame leaves the wrong one bound and the rest of the frame lands off screen.
  - The shader links on the driver's threads (`Program::finish` checks without waiting; panels paint solid until ready). Waiting froze start for 10+ s. Keep the shader small: every call of a big GLSL function is inlined into the HLSL.
  - Speed: about 0.1 ms a frame at full GPU clock (`KRITA_DEV_FRAMELOG` logs "glass gpu: shrink, blur, draw"). The GPU drops its clock under this light load, so compare timings at equal clocks (`nvidia-smi --query-gpu=clocks.gr -lms 200`) or against a stage left unchanged. The D3D compiler computes every branch of a function chosen per pixel: read each frost level in one place behind its own weight, with `textureLod` (no derivatives). The vertex shader's reads wait one after another: written out a row at a time, they overlap. The mean chroma comes from the blur's weight channel (weight = 1 + salience × chroma), so there is no separate statistics blur.
  - Glass masking skips windows that are ancestors or descendants of each other (a glass panel inside a glass flyout). It masks everything stacked over the canvas (`overlaysOf`, the start page's scroll area too), so it stops while the canvas is hidden; Qt doesn't repaint what a lifted mask shows again, so `hide()` does (tooltips left their shapes on the start page).
- **Effects on the canvas** (`KisStudioEffectOverlay`, `KisFilterManager::setInlineEditor`): any filter previews live on the layer with a small draggable glass panel; Enter keeps, Esc drops, the mask button keeps it editable. It opens with the last applied settings (`KisFilterManager::lastUsedConfiguration`), reset shows while they differ from defaults. Picker tiles render with the same settings at the thumbnail's level of detail, each into its own device. The panel goes in the widest free stretch of canvas; its settings grow to 65% of the canvas's height before they scroll (`settingsRoom`; a fixed 560 px cut Drawing off on a 1440 px screen). While open, autosave waits (`autosaveHeld`) and a busy image is waited on quietly instead of Krita's modal "Waiting…". A preview may never write the real device outside a `KisTransaction`. An effect's settings widget that implements `KisEffectCanvasEditor` (found with `qobject_cast`) gets the pointer over the image and drags on it instead of the first-numbers drag. One with a middle (`canvasMiddle`: Lens, Radial blur) has it drawn on the canvas as a handle (`MiddleMark`, a child of the canvas widget following `sigCanvasStateChanged`, only as large as what it draws) under a crosshair; one with a sample of what it does (`canvasStreak`: Radial blur's streak) has that drawn by the middle, a fixed size on screen, ending in a knob that drags (`canvasStreakDragged`). The eye is instant both ways: it switches what the canvas shows, the picture as it was when the effect opened (`before`, through `KisOpenGLImageTextures::setShownInstead`) or the image, and the preview keeps following changes underneath; a canvas without OpenGL still cancels and reapplies, and so does a view zoomed out with instant preview, where the preview exists only at a level of detail (the image itself has no effect until it is applied, so the canvas made again from it showed none: the eye seemed to drop the effect).
- **Effects, by what they do to a pixel** (the plan the owner agreed to): Color (by its own color), then Detail (one curve over feature size: blur, sharpen, high pass, noise reduction, with one-slider presets like Gaussian blur), Noise (white noise shaped by that same size curve), Lens (physical: dispersion, fringes, distortion, cos⁴ vignette, glow), Radial blur (zoom, spin, light rays), Drawing (difference of Gaussians: lines with ink, pencil, hatching, strokes, dots, a print screen, engraving or contours), Fewer colors (posterize, palette, dithering in OKLab, pixel art), Shape (the layer's distance field: outline, glow, shadow, grow), Light (bright parts scattering light: glow, star, streak), Painting (anisotropic Kuwahara) and Replace color, plus shader effects. Krita's effects one of them does entirely are retired (`KisRetiredEffects::coveredBy`), and the dated or narrow ones are left out (`isLeftOut`: Wave, Raindrops, Small tiles, Round corners, the Embosses, Edge detection, Phong bump, Dodge, Burn, Tone/Gamut map, Fast color overlay, Color transfer, Height to normal map, Reset transparent): not in Find or the picker, still registered so files and masks render, and still in the classic Filter menu; favorites of left-out ones go; favorites of them become the new effect, and the keys of those it opens instead (Ctrl+M, Ctrl+U, Ctrl+L, Ctrl+B, from Krita's shortcut schemes) open it (`replacement`), set to do what the old one did where that takes a setting (`replacementSettings`: Halftone opens Drawing's screen, Pixelize Fewer colors' pixel art, Gradient map Color's map). Common uses of one effect are effects of their own with a slider or two (Blur, Sharpen, High pass, Smooth are Detail), so the simple thing stays one click and one slider. Upstream Krita can't render a mask of a Skissa effect, except Blur, Sharpen and High pass, which are Krita's Gaussian blur, unsharp and gaussianhighpass by id and settings (Skissa makes their blurs and honours Krita's settings it doesn't show: a blur stretched one way, lightness only, threshold; Krita's own Unsharp and High pass aren't built, its Gaussian blur isn't registered; the `skissa_*` ids from before still open). Applied effects are plain pixels.
- **Color effect** (`plugins/filters/skissa_color`): curves of lightness, chroma and hue by each of them in OKLCH (the diagonal maps, the rest shift or scale; the hue axis is spaced as an HSV wheel, `axisOfHue`), red, green and blue curves, a white balance (von Kries in Oklab's cone responses, `Recipe`) and shadow and highlight tints as discs. Exposure, contrast, vibrance and saturation are curve shapes, not sliders (the owner's call). Curves are monotone cubics (no overshoot); a curve by hue wraps and its ends are one point. Tiles of the layer under a few starting points (Auto stretches the lightness between the half-percent ends). A drag up or down on the image bends the shown curve at that pixel's value, read from a copy taken before the preview (`KisPaintDevice` copy, tiles shared); on a curve by hue it holds the curve a twelfth of a turn either way, so one hue changes alone. Settings files hold only what differs from the defaults. Integer images are kept in gamut by giving up chroma (`KoOklch::inGamut`), past white as a near-white is (`fitted`: cut channel by channel, pure white turned cyan beside a neutral 254), and white balance scales its gains so white itself stays inside (`m_whiteKept`), so paper takes the grays' cast; float ones keep what is past sRGB. Its last tab, Map, is the gradient map, applied before everything else: each pixel's Oklab lightness becomes the stops' color there, blended in Oklab or the nearest stop's (Steps), with Keep lightness (the map gives only hue and chroma) and Strength; looks as tiles (Picture: five stops of the layer's own colors by lightness, to edit from), the stops on `widgets/KisStudioGradientBar` over the layer's lightness, and a press on the image takes the stop at that pixel's lightness (or adds one) while a drag recolors it (up lighter, sideways around the hues). It retires Krita's Gradient map, whose panel stays for old masks.
- **Detail effect** (`plugins/filters/skissa_detail`): gain over feature size, as the image times the finest features' gain plus, for each radius where the gain changes, the image blurred to it times the change (`Plan`); so Blur, High pass and Sharpen are exactly one step, with Krita's radius (sigma 0.3 r + 0.3). Its curve is sampled every half octave from 1 to 1024 px. Blurs under sigma 4.5 are Krita's kernel; wider ones are made on a pyramid shared by every step (`Pyramid`: halved by a 1 5 10 10 5 1 binomial, the blur made exactly on the coarsest level where it spans two cells, enlarged by a cubic B-spline whose variance is taken off): within 1/40 of an 8-bit level of an exact Gaussian on a hard edge, the image's edge repeating as in Krita's blurs, and any size costs what a small one does. The edge-aware blur finds its two coefficients on the level's cells too. Clarity on 8 MP went from 45 s to under 3. What a curve takes of the largest shapes becomes middle gray (high pass); transparency only ever blurs, and where a step changes the colors and the transparency apart (sharpening a cut-out), the colors it adds are the visible ones around, its blur divided by the blurred alpha, times the pixel's own alpha (blurred with the clear pixels, they counted as black and lit a rim inside every edge). A smaller copy (a level of detail) scales the blur's sigma, not Krita's radius. Edges make each blur a guided filter on luma (Rec. 709 weights of the channels it blurs; epsilon (0.02 / edges)²). Beyond the image its edge repeats, as Krita's blurs do. A press on the image finds the size that stands out there (`busiestRadius`) and a drag up or down changes it alone. The curve editor is shared with Color (`widgets/KisStudioCurve`).
- **Noise effect** (`SkissaNoise` in `plugins/filters/skissa_detail`): white noise from a hash of the pixel and the seed (the same wherever and however often it is drawn, so patches meet), split into Detail's half-octave bands, each brought to unit spread (exactly, from the 1D kernels' overlaps) and to the strength the size curve gives it. Bands of large sizes are made on grids a power of two coarser and enlarged bilinearly, so clouds cost what grain does; those grids are anchored to the full image's pixels, so a preview at a lower level of detail shows the clouds the image gets. One field per target: lightness and color in Oklab (two fields), transparency, Displace (two fields: fine scatters, large wobbles). Midtones weighs lightness noise toward the middle tones; near black, and near white where the picture stops there, the noise stays within two spreads of the end (cut on one side it darkened whites and lifted blacks), so grain fades into paper white and solid black. The dice gives another seed. Grain is Noise with Amount, Size and Color; it replaces Random noise, Noise replaces Random pick.
- **Lens effect** (`SkissaLens` in `plugins/filters/skissa_detail`): what a camera lens does, in linear light, with every size a share of the half diagonal (so a look is the same on any image and at any level of detail). Fringes: each wavelength magnified by 1 + fringes × its dispersion (Cauchy, in units of the F and C lines), sampled at even steps of dispersion a pixel apart at the farthest corner (8 to 48) and weighted by the CIE 1931 fit turned into sRGB, negatives dropped, each channel's weights adding to one; nothing moves at the middle. Halo: red and blue (or green, below zero) blurred as if out of focus. Bulge: r (1 + k r²), a barrel keeping the farthest corner in place. Vignette: cos⁴. Glow: light moved, not made, to sizes an octave apart in equal shares, the large ones blurred on coarser grids made straight from what was read; in an image that stops at white what spreads is the light its whites stand for (`unclipOf`), so a white lamp blooms instead of dimming. Glow size shows only while there is a glow. Coverage is carried per channel, so a see-through layer's fringes stay inside what is there. A press on the image places the middle (`KisEffectCanvasEditor::canvasDragged` gets the point under the drag). It reads from anywhere in the frame, so its needed rect is huge and the coarse preview chooses its level by pixel count alone (`KisCoarseFilterPreview::level`). 24 MP: about 1 s for a fisheye, 2 s for Vintage. Nothing of Krita's is retired by it.
- **Radial blur** (`SkissaRadial` in `plugins/filters/skissa_detail`): zoom, spin (both at once a spiral) and light rays about a middle, in linear light. Each pixel averages along its streak, the orbit of one zoom-and-turn (a log spiral; rays for zoom alone, circles for spin alone), weighted by length and fading as a square from the pixel (`back` of it beyond the pixel for spin, so shapes stay put). Streaks are straight lines in log-polar coordinates, so each patch sums lines a fixed step of λ = θL − uA apart once (running sums of the picture times 1, s, s², in doubles: floats lost whole levels where a turn's long lines cancel; only the channels the look uses; samples stepped by a complex multiplication, a new step every octave of radius) and each pixel reads the two either side: a long streak costs what a short one does (8 MP in about 0.5 s, as Lens 0.4 s). The lines are the same in every patch (a whole number around a turn, coarser by powers of two where a patch's streaks reach less far), so patches meet within a few levels at hard edges. Picture is how much the picture itself streaks. Light: what shines as Light finds it (`SkissaPixels::shineOf`) past Threshold × the layer's brightest parts (`top`, its 99.5th percentile, found by the panel and kept in the settings), scaled so the brightest parts give their own color, averaged along the streaks and added as light (over clear pixels as opaque as it is bright); shapes in front cast shadows in the rays; an absolute threshold left night scenes without any. Shafts break the light into beams where it starts (smooth noise by angle, a dice for others), so rays show in open sky. A press on the image places the middle (it may lie past the edges) and a drag moves it; the streak drawn by the middle has its end as a knob: in zooms, around spins, the two sides shared as the effect shares them, so the knob stays under the pointer. Pulling streaks anywhere on the image with nothing drawn was tried and read as unintuitive.
- **Drawing** (`SkissaInk` in `plugins/filters/skissa_detail`, id `skissa_ink`; it was called Ink): the picture drawn by hand, its lines by the extended difference of Gaussians (Winnemöller's XDoG) along the picture's flow (Kang's FDoG), after Acerola's shader, with all its parts behind three choices. What is drawn, four rows that always show: Size (the blurs: Size and 1.6 × it), Lines (the sharpening, p up to 100 as a square; differences under 0.006 dropped, or 8-bit gradient steps show as stripes), Shading (a share of the layer, darkest first: the panel finds the lightness it reaches, `level`, kept in the settings, so a look reads alike on light and dark pictures), Flow (the structure tensor of Oklab, Sobel smoothed by 1.5 + Size, gives the direction along edges; the lines are smoothed along it by a line integral of a third of its sigma a step, then their edges by a pixel; the picture under the ink too, for Picture and Colors: Wash; each sample counts by how close its lightness is to the start's, none a tenth or more apart, `edgeRange`: smoothed regardless, eyes melted into blobs and a ring across a pen was smeared along the pen into hairs). How the shading is drawn, as tiles, each with its own settings (`Shading`): Solid (steps of hard ink), Soft (one threshold as soft as asked, and Grain: the paper's tooth, `toothOf`, catching the ink on its peaks first, a threshold of evenly spread heights, so the tone stays, never so soft that bare paper catches some or full ink leaves some: pencil, charcoal), Hatch (`hatchAt`: three directions, the second crossing; rows by rank, every fourth first, then every second, then all, each coming in thin and widening over a quarter of its range so rows taper where the shading ends; long strokes with small gaps, each a little off its row and tilted; covering as much as the picture is dark, `hatchCovers`: the first direction, then the crossing ones over it, then all pressed wider with shorter gaps until they close; filled by thirds of the darkness, mid-tones came out a third as dark as they should), Strokes (the XDoG paper's own hatching: white noise fixed to the image's pixels, filtered across the flow by a broad Gabor kernel into stripes Spacing apart and along it by a line integral into strokes Length long (`strokeAlong`, turning with the flow every third step; reading the nearest pixel instead of between pixels made them grainy, a step of two pixels dotted), `stripesOf`, made on a grid a fifth of a stripe apart once stripes are 10 px or wider (coarser read as blotchy), brought to unit spread around each place and cut where a normal quantile makes its coverage; past 55% a second set turned a third of a turn crosses it (square to the first, it read as a weave); their flow is smoothed more than the lines' and turns toward 45° where the picture is calm), Dots (stippling, `dotOf`, each cell's dot found once per patch: one dot per cell of a jittered grid, there where the darkness passes the cell's rank in blue noise, `SkissaFewer::blueNoise`, so dots never clump; small near their rank, growing past touching at the darkest; how much the grown dots cover is measured once, `dotsFor`, so the tone stays where they overlap), Screen (a print screen: the Euclidean dot on a turned grid, its level found from the dot's own area so coverage is exact, `spotLevel`; with Colors, cyan, magenta and yellow screens at their own angles under the ink's black: pop art), Engrave (parallel lines bent by the picture's lightness blurred at their spacing, each as wide as the share of its spacing that is dark), Contour (lines where the darkness passes each of Levels steps, bolder where darker); both count the line beyond the nearest (`bandsOver`), or the darkest never close. Screen and Engrave cover the tone as print does (coverage 1 − (L/level)³), the others lighter, as drawing does. Marks take their darkness evenly from the picture's lightness below the level, and lines stay whole over them: the edges alone, as they would be drawn on the paper's white (1 + edges against the level); added to the picture's own tone, they showed only where it was lighter than the level, and vanished under every mark. Every threshold is averaged over its pixel from how much D changes across it (`inkOver`, the tanh's integral), so edges are smooth however hard; marks are fixed to the image's pixels. Where the ink goes: Paper, Clear (line art pulled off its paper), Picture (over it), Colors (the picture's colors as ink, deepened as pigment laid twice). Tried and left: hatching as a percentage mixed with flat ink, Flow switching hatching to strokes, rows appearing by hidden rules (all read as confusing); straight lines widening with the tone as hatching (a mechanical screen; it is Screen and Engrave's look, where print is meant); thresholding noise smeared only along the flow (bands and blotches; it needs the band-pass across it); random dashes along hatch rows and white-noise dot ranks (both read as noise). Marks are drawn after the lines' smoothing, not smoothed with them. Looks as tiles of the layer's busiest part at half size, two rows of six (drawn with lines and tone: Lines, Ink, Comic, Pencil, Charcoal, Wash; with marks: Hatching, Etching, Stipple, Engraving, Halftone, Pop art; the owner found three rows too many; the shading kinds in one row of eight, so the panel fits), made off the window's thread after a pause, as are the shading and placement tiles; a drag on the image: up for more shading, sideways for size. 8 MP in about 0.4 s of work (Strokes more). It retires Krita's Halftone (its diamond, square and wave shapes aren't carried; old masks keep Krita's panel).
- **Fewer colors effect** (`SkissaFewer` in `plugins/filters/skissa_detail`): each pixel takes the nearest of a few colors in Oklab (`Quantizer`): steps of each channel on the sRGB curve (posterize, up to 32), grays even in Oklab lightness, colors found in the layer (k-means++ in Oklab on a thumbnail, done by the panel) or a palette's; the image's and palette's colors are kept in the settings, so patches, masks and previews agree. Lightness moves where the steps fall (Threshold is two grays). Pattern (Bayer) and Noise (void-and-cluster blue noise, made once) are Knoll's pattern dithering: 16 candidates that average to the pixel in linear light, picked by the threshold, fixed to the image's pixels. Diffuse (serpentine Floyd and Steinberg, error in linear light) runs through the whole image once and every patch takes its part: the result is found again by a key of the original pixels and the settings (`SkissaPixels::originalKey`), since a mask's patches each get a copy of their own. Pixel size above 1 is pixel art (`cellColors`): cells fixed to the image's corner, each one color, then fewer colors and dithering per cell (a pattern by cell, diffusion through the cells of the whole image). A cell is in the picture or out of it (alpha 0 or 1). A cell of one color takes its average; a cell of two (two means in Oklab with alpha) takes the larger, or the other where it stands out from the eight cells around and is more than a fifth of it, so thin lines and the dark side of edges stay whole instead of blending into a color in neither (a local stand-in for Kopf et al.'s content-adaptive downscaling, which optimizes each cell's footprint over the whole image). It retires Posterize, Threshold, Palettize, Index colors and Pixelize. Colors found in a layer aren't carried to the next by the last used settings (`lastUsedConfiguration`).
- **Shape effect** (`SkissaShape` in `plugins/filters/skissa_detail`, id `skissa_shape`): the layer's shape from its exact distance field (Felzenszwalb and Huttenlocher, two passes of lower envelopes of parabolas, keeping which pixel is nearest, `nearestOf`; not jump flooding, which is the GPU's approximation), the edge found between pixels from the nearest opaque pixel's alpha, so any width is smooth and costs the same; only a pixel beside the other side holds the edge (deeper in, paint less than solid is see-through paint), and alpha counts as a share of the layer's solid paint (`solid`, found by the panel: all but a hundredth of its painted pixels are at most that opaque), so a layer painted at 40% still has a shape. Grow (positive grows, its new pixels the nearest edge's color: bolder line art; negative shrinks), Outline (Outside under the shape's soft edge, 3 px in, so the two meet without a seam; under the whole shape it tinted see-through paint; Center and Inside over it), Glow (a Gaussian falloff from the silhouette's edge), Shadow (the silhouette, the outside outline in it, moved and blurred; none at distance 0). Each is a tab with a dot while on; looks combine them (Sticker: white outline and soft shadow; Neon). A drag on the image moves the shadow in its tab, elsewhere sideways is the part's size.
- **Light effect** (`SkissaLight` in `plugins/filters/skissa_detail`, id `skissa_light`): bright parts scattering light, added in linear light. What shines is brighter (cube root of luminance) than Threshold × the layer's brightest parts (`top`, as Radial blur), with a soft knee, and the whitest parts count as the clipped light they stand for (an inverse Reinhard curve, up to ten times; not in float images, which hold their light): without it an 8-bit sun barely glowed. That is `SkissaPixels::shineOf`, shared with Radial blur's rays; Lens's glow spreads the same unclipped light (`unclipOf`). Saturated colors don't shine by themselves: pure paint can't be told from a light, and painted lights have white cores. Glow is glare falling off about as r^-2.6 (Gaussians from 1.5 px to a third of Size, evenly by ratio at most an octave apart, each weighed by that power and the share of the range it stands for: fixed octaves made Size move in jumps); Star is diffraction spikes (Points, Length, Angle), each wavelength's a different length so the ends turn red; Streak is an anamorphic line in its own color. Spikes are made on a grid fixed to the image's pixels (64 cells along a spike) and enlarged; their fade is a recursive filter run both ways along the rows of the grid turned to the spike's direction (`addSpikes`), so a spike of any length costs a few passes (summing each spike's samples took seconds). The glow's octaves are blurred on the coarsest level of a pyramid of the shine that still holds two cells of them, cells fixed to the image's corner. A huge bright area makes haze, not a star, as a lens does. 8 MP in about 0.25 s.
- **Painting effect** (`SkissaPaint` in `plugins/filters/skissa_detail`, id `skissa_paint`): the anisotropic Kuwahara filter (Kyprianidis, Kang and Döllner) with polynomial sector weights (Kyprianidis 2011): an ellipse along the flow of the structure tensor of its Oklab colors and coverage (of lightness alone, edges between equally light colors and white shapes on a clear layer had none), eight overlapping sectors, each pixel the sectors' means weighed toward the calmest (1 / (1 + (1000 σ²)^(q/2)), in Oklab with alpha). The sector weights put the disk at radius 1 (at a half, as some shaders scale it, every sector covered everything and the result was a plain blur). The ellipse is read at 48 sunflower points, precomputed with the sectors they count in, each at its nearest pixel (bilinear reads cost twice as much and looked the same), and the sector weights' power is a rough one (`roughPow`); past a radius of 8 the picture is blurred first by a tenth of it. Size, Sharpness, Flow. It covers Krita's Oil paint. 8 MP in about 0.55 s.
- **Effect panels** (the owner's ask: simple, minimal, obvious): what an effect can do as pictures of the layer, each setting a `KisStudioValueRow` (drag, a click on the bar sets the value there, `setClickSetsValue`, double-click on the number types, right-click resets; never Krita's slider boxes, whose whole-range switch read as clutter), one per line, and a drag on the image for the main value. Fewer colors: where the colors come from as pictures of the whole layer (Picture, Gray, Palette; Levels only while a setting uses it), Colors, Pixel size, Brightness, dither ramps, Amount. A drag on the image follows one rule: up or down is the effect's amount, sideways its size, and a press places the middle where there is one (Lens, Radial blur); Detail, Noise and Color's curves go up or down only. The effects of a slider or two (`SkissaSliders`: Blur, Sharpen, High pass, Smooth, Grain) are canvas editors too: up or down their Amount (or their only size), sideways their size; the overlay's own first-numbers drag finds only Krita's spin boxes and sliders. The pointer over the image says which ways (`KisEffectCanvasEditor::canvasAxes`: both, up or down, or a crosshair for a middle), and the values show in a pill from the press on. Directions are `KisStudioValueRow`s with `Range::angle`: a dial before the number, turned by dragging around it (`dialTurn` when the value names the direction across what it is about, as Drawing's angle does).
- **Replace color** (`SkissaReplaceFilter` in `plugins/filters/skissa_detail`, id `skissa_replace`, its panel `replaceColor` in `KisEffectPanels`): one color made another or see-through (With's alpha), a pixel holding some of it read as the color with paint over it, that paint laid over the new color (`replaceShare`), so soft edges keep their blend; on the values as the image keeps them, which Krita blended in. Two ways, as tiles: Background (the color under everything, GIMP's color to alpha, `shareUnder`; mixes of colors that cancel to gray aren't read as the color) and Color (`shareBeside`: only the color and its blends, found by walking the picture's slope up to 64 px each way: downhill it must come to the color without crossing an even patch over 8 px, uphill the blend's other end). Plain color to alpha for a fill color read skin as a third red and turned the gray edges of black lines teal; a fixed ring of neighbours left soft strokes half done with a blocky ring. A press picks the color and the way: Background when the color is 30% of the layer or more. Range (drag up or down on the image) is what counts as the color; a hairline that never reaches its color needs it raised. It retires Color to alpha.
- **Hidden colors** (`KisHiddenColors`): erasing lowers only alpha, so clear pixels keep what was erased; PNG export writes them cleared (`KisPNGConverter::buildFile`), as GIMP does, and Export's sizes count without them. WebP drops them itself; .kra keeps them.
- **Panels for Krita's effects** (`KisEffectPanels`, asked for by `KisFilterSelectorWidget::setFilter` before the filter's own; Halftone, Pixelize, Gradient map and Color to alpha are retired and Height to normal map left out; their panels stay for old masks): Halftone (shapes, Paper/Clear/Color, Size, Angle, Softness, Ink and Paper), Desaturate (its ways as pictures; Ctrl+Shift+U opens it), Motion blur (a drag on the image draws the motion), Lens blur (iris shapes drawn), Pixelize, Color to alpha (a click on the image picks the color), Propagate colors, Height to normal map, Gradient map (looks, a bar of stops: drag, click adds, right click removes; Smooth/Steps/Dither). Each writes Krita's settings as Krita's own panel does (Halftone's screens are flat `<screen>_generator_screentone_<key>` properties; Lens blur's `halfWidth`/`halfHeight` follow the iris), so files and masks stay Krita's. A `Panel` is tiles (`Pictures::Detail` a busy part at its own size, `Whole` the layer small, `None` words; `forPictures` changes what only the tiles' pictures use, as Halftone's screen kept to a third of a tile), value rows, colors and switches; pictures run the filter itself on a copy, which needs `cloneWithResourcesSnapshot` and the layer's default bounds (Krita's blurs assert without them).
- **A preview never shows the layer half done.** A single layer (or a group's only child) is the image's projection itself (`KisGroupLayer::tryObligeChild`), and the canvas reads the projection right after each merge, on the merge's thread (`sigImageUpdated` is a direct connection). So in `kis_filter_stroke_strategy.cpp` everything that writes or takes back the layer while merges may run waits for them first (barrier jobs) or asks for no update until it is done (`disableDirtyRequests`): the coarse pass taken back on cancel and before the full pass, the coarse pass written. A dragged Blur flickered to the unblurred image at about every step before. To test it, read pixels on the merge's thread like the canvas; a queued slot reads later and sees states the canvas never shows.
- **Preview passes** (`kis_filter_stroke_strategy.cpp`, `coarsePass`): a coarse pass at once (enlarged with colors weighted by alpha, `KisCoarseFilterPreview::upscale`, or clear pixels darken the edges beside them), then (zoomed out with Krita's instant preview off) one at the canvas's own resolution (`displayLevel`), then the full pass after a short settle (`qBound(40, estimate / 8, 400)` ms); each is written over the one before in one step. Zoomed out with instant preview on, Krita's own level-of-detail stroke previews instead.
- **Pictures that show little**: an effect's pictures (the picker's, a panel's tiles, Detail, Noise, Lens, Color) use the sample painting (or Detail's zone plate) when the layer's picture shows too little to see an effect on (`KisEffectPanels::showsLittle`: what differs from the commonest color, thinned 2 px from every side, under a twelfth of it left): thin line art on clear or on paper. Fewer colors keeps the layer: its colors come from it.
- **Filter patches** are sized from how far the filter reads around them (`neededRect`, `patchSizeFor` in `kis_filter_stroke_strategy.cpp`): with 512 px patches a wide blur read 15 times its area for each.
- **Effects read the pixels as they were** (`SkissaPixels::readOriginal`, the transaction's old data): patches run side by side in one layer, and `readBytes` would read a neighbour already written.
- **Brush editor rows** (`kis_paintop_option`, `kis_paintop_settings_widget`, `kis_categorized_item_delegate`, `plugins/paintops/libpaintop`): each option's row shows its strength (`KisPaintOpOption::RowValue`): drag, double-click to type, right-click for the value from when the brush was picked (`rememberRowValues`); 100% is hidden until hover; the lock is an icon. Qt repaints every widget over a GL canvas whenever the canvas is dirty in the same frame as any other widget, though they hold none of its pixels (7–10 ms a frame with panels open): the pacer shows a changed canvas in a frame of its own after the widgets (`KisUpdatePacer::presentCanvas`), where Qt draws it alone. The pacer slows by a refresh at a time (to every fourth at most) only when half of the last sixteen frames were late. Things a drag changes at every step must repaint only what changed: chips set again unchanged aren't repainted (`Chip::pictureKey`), an effect panel's row refreshes only visibility and tiles, its overlay doesn't raise itself when on top (a raise repaints it whole), and pictures made from the layer wait for a pause (Fewer colors). A value row's bar follows the pointer, not the value's steps (`m_dragged`): stepped, it read as low fps. Measure with `KRITA_DEV_FRAMELOG` (`shown` and `canvas shown` lines, each paint with its widget and rect); dev input drags must arrive synchronously (`KritaDevMouse`), or posted messages starve Qt's own events.
  - Krita keeps a tool manager per window: reach it through `KisStudioTools` and connect each part to its own window's.
  - Keys belong to the canvas (B, E, Space, Tab are the painter's): a field done with (Enter, Esc) and a panel, flyout or inline edit hiding while it holds the focus give it back with `KisStudioTools::focusCanvas`, not to whatever Qt picks next. A slider box counts as a text input only while its text is being typed (`isTextInput` in `kis_input_manager_p.cpp`); buttons and switches in panels take no focus.
  - Overlays stay on top with `KisStudioLayout::keepAbove`; raise only what is being dragged (two overlays raising themselves swap and repaint forever).
  - Shared helpers, one copy each: sRGB and Oklab (`KisColorMath.h`), color mix (`KisModernStyle::mix`), search scores (`KisStudioPicker::matchScore`), popup shadow room (`KisStudioGlass::shadowMargin`). Look for one before writing another. Older copies remain (Oklab in the composite ops, glass, Color, Drawing and mixing; Find's and Settings' own scores): fold them in when touching that code.

## Dev workflow (Windows)

The build environment is outside the repo, in `C:\code\krita-deps`: llvm-mingw, KDE's prebuilt Qt5 deps in `env\_install`, the build dir `build`, helper scripts in `devtools`, and in its root `run-krita.bat`, `profile.py`, `baseline-tests.bat` and `known-failing-tests.txt`.

- **The fork's own files in `libs/ui` are listed in `libs/ui/skissa.cmake`**, not kritaui's list (they rebuild in ~5 s instead of ~14 s). Add new `libs/ui` files there; form headers (`ui_*.h`) they include go in `kritaui_skissa_forms`.
- **One command:** `devtools\dev.ps1` builds, closes the dev Krita and waits, installs and launches (~10–20 s). Flags: `-NoBuild`, `-NoLaunch`. Build errors are matched case-sensitively; cmake's Python `ModuleNotFoundError` lines are harmless. After a build, check the installed DLL's time: an install can keep the old one if the dev Krita was still running. Two sessions building in `build` at once break CMake's regeneration: build again.
- **Always run the dev build through `run-krita.bat`** / `launchdev.ps1` (hidden console). It sets `KRITA_DEV_PROFILE=1`, so settings and resources live in `%LOCALAPPDATA%\qttest` and `%APPDATA%\qttest`. **Never touch the owner's real Krita profile** (`%LOCALAPPDATA%\kritarc`, `%APPDATA%\krita`).
- **Driving the app:** the dev build listens for posted window messages (`krita/KisDevHooks.cpp`): `KritaDevCapture` (renders its own windows to a PNG; no screen capture, ever), `KritaDevMouse`, `KritaDevKey`, `KritaDevTree`, `KritaDevExport` (.kra; wParam 1 TIFF, 2 PNG, which asks for its options first), `KritaDevShortcuts`, `KritaDevColorDrop`, `KritaDevAction` (`devtools\action.ps1 -Name krita_filter_halftone` opens an effect; any action id runs it, the window's own too: `show_brush_editor`, `studio_effects`, `find_anything`, `options_configure`). Helpers in `devtools`: `devinput.ps1` (move, click, rclick, line, drag, type, key, capture), `pen.ps1` (a pressure stroke), `penrate.ps1` (`-Mouse` drags, `-Hover` moves, at a steady rate), `fxtime.ps1` (each effect's preview time, opened twice: the first opening carries one-off costs), `threads.ps1` (CPU per thread while a script block runs, named by start module), `colordrop.ps1`, `tree.ps1`, `kritawin.ps1`.
  - Captures miss QPainter-only canvas decorations (guides); GL-drawn tool outlines show.
  - Captures redraw every window, so stale pixels never show in them. `KritaDevCapture` with wParam 1 saves each window's backing store as it is instead (no GL canvas in it, see-through glass transparent): use it for anything "left behind".
  - Synthetic moves don't move the OS cursor: use the event's `globalPos`, not `QCursor::pos()`. They do hover item views (with `WA_Hover` on the viewport).
  - Synthetic presses go to the topmost window, a tooltip too: move and press without waiting. Capture before clicking by coordinates; the owner may have moved the bar.
  - Synthetic drags don't move the tip editor's chips or Grow/Soft scrubbers: test those through what they change.
  - In popups, `QContextMenuEvent::pos()` can be in window coordinates: map from `globalPos()`.
  - In a fresh profile (`KRITA_DEV_APART`) the UI scale differs, so devinput coordinates are logical pixels.
- **The shell sees a stale copy of `%LOCALAPPDATA%`** (the desktop app is an MSIX package). To read or edit the real dev `kritarc`, copy it with a WMI-launched process (`Invoke-CimMethod Win32_Process Create`), and edit it only while the dev Krita is closed. Console programs started through WMI hang when Windows Terminal is the default console: start them detached (`CreateFlags = 8`, `ShowWindow = 0`).
- **Back up the dev profile right before each test that writes to it,** and restore exactly what was there; the owner works in the dev build between turns. Prefer the UI (with the panel's Undo) over editing files. Ctrl+Z in a test also undoes settings toggles.
- **It's fine to close the dev Krita** (unsaved changes and all) to rebuild. Only kill processes whose path is under `C:\code\krita-deps` (the owner's installed Krita may be running; scripts look for `skissa` and `krita`). After a kill, delete `.sunset.png-autosave.kra`, or the next start waits on recovery.
- Another session may be driving the dev Krita (maybe with other variables): a fresh-looking profile in a capture may be that, not the code.
- **README clips:** `devtools\rec.py` drives the app and captures frames (stop-motion, ~1 s a capture); save as animated WebP.
- **Pen-to-pixel time:** `devtools\latency.ps1` (with the dev build closed; `-Running` measures one started that way) paints scripted strokes at a pen's report rate (`penrate.ps1`) with `KRITA_DEV_LATENCY` and prints each stage's median/95th/worst ms (`KisPenLatency`: arrived, dabs handed to the engine, merged into the image, taken by the canvas, frame drawn). At 200 Hz: about 11 ms median, 13 at the 95th; 5 of it is the wait for the next report (each curve piece is painted once the report after it gives its tangent), every other stage under 2 ms. A pen that stops before lifting gets its last piece after three of its reports (20–100 ms, `reportSpacing` in the freehand helper; Krita waited 100 ms). Check the canvas is OpenGL (`KRITA_DEV_FRAMELOG` names `KisOpenGLCanvas2`): the spare profile has had OpenGL fail and measured the QPainter canvas.
- **Startup profiling:** `KRITA_DEV_SAMPLE=<file>`, then `profile.py <file> --timeline 250` (`--callers`/`--callees`). `QT_LOGGING_RULES=krita.performance.debug=true` prints Krita's phase timings. Most start time is Krita's. `KRITA_DEV_FRAMELOG` gives each frame's cost and paints.
- **UI tour:** `KRITA_DEV_TOUR=<folder>` runs `krita/KisDevTour.cpp`, photographing the whole UI (the crash sweep); `devtools\tour_index.py` and `tour_maps.py` index it. Run it with `KRITA_DEV_APART=1` after closing the dev Krita (a second one hands itself over), and not while tests build. It picks what to press by text, tooltip, object or accessible name: unnamed buttons may get Close pressed. Every early return in a step must `end()` it. Its photos have artifacts (popup order, pointer-placed pickers, transparent glass dialogs): check findings by hand.
- **Tests:** `devtools\tests.ps1` builds unit tests in `build-tests`, runs them, reruns failures one at a time, and reports failures untouched Krita doesn't share (`known-failing-tests.txt`, checked against `build-upstream` with `baseline-tests.bat`). Run after merges from Krita and changes to Krita's code (libs/image, pigment, flake, formats). Tests load plugins from the install: `dev.ps1 -NoLaunch` first when testing a plugin. A timeout of `TestCompositeOpInversion` on a busy machine isn't a failure (`--timeout 900`).
- **Test images:** `C:\code\krita-deps\sunset.png` (the `launchdev.ps1` default); `glass-test.jpg` is the Krita artwork.

## Updating from Krita

`origin` is Krita (KDE), `skissa` is the fork's own repo. Merge Krita in often (small merges are easy); never rebase the branch.

- **One step:** `devtools\update.ps1` runs `packaging/skissa-update.py`: fetch, merge (rerere on), translations refreshed and committed, build, install, start and capture. Exit 2 leaves the merge open: settle, commit, run it again. Check the capture, then push.
- **Check a merge first:** `git merge-tree --write-tree --name-only HEAD origin/master` lists the files that would conflict.
- **Keep Krita's files mergeable:** new code in new files called with a line or two; turn Krita's code off in CMake rather than deleting it; don't append to Krita's lists when a fork file can hold it (`po-skissa/`, `libs/ui/skissa.cmake`).
- **Skissa's own copies of Krita's files**, built in their place: the layer, palette and time-lapse panels (`plugins/dockers/skissa_layers`, `skissa_palette`, `skissa_recorder`) and Multibrush (`KisStudioMultiBrush`). Krita's fixes to those don't merge: the update script lists Krita's commits that touched them (`KEPT` in `skissa-update.py`) to bring over by hand.
- **Where the fork still changes Krita's code most** (candidates to move behind a call): `KisMainWindow.cpp`, `kis_tool_freehand_helper.cpp`, `plugins/paintops/libpaintop` option widgets, `kis_preset_chooser.cpp`, `kis_paintop_settings_widget.cpp`, `KisOpenGLCanvasRenderer.cpp`, `kis_config.cc`, `kis_slider_spin_box_p.h`, `kis_cmb_composite.cc`, `kis_paintop_box.cc`, `KisTagChooserWidget.cpp`. About 40 of Krita's files only change "Krita" to "Skissa" in their text.

## Lessons (append, newest last)

- Check the dev profile's state before blaming code: a "wrong" value is often a setting.
- Count only deliberate input as "the user is working": pen hover sends moves all the time.
- Public text (README, release notes) is shown, not told: a clip or screenshot per feature, a line of plain first-person words at most. Release notes are pictures and a line or two of facts. Selling, bold lead-ins, feature lists and comparison tables read as marketing or machine-written to the owner.
- Windows caches program icons by path: after the .exe's icon changes, `ie4uinit.exe -show` refreshes it.
- Python one-liners in a bash heredoc turn `\n` inside C++ strings into real newlines: make escape-heavy edits with the Edit tool.
- PowerShell's `[int]` rounds to even: use `[math]::Floor` in test scripts. `Set-Content -Encoding utf8` writes a BOM, which CMake files can't take. `Copy-Item` keeps the old modified time, so ninja won't rebuild a copied-back source: touch it.
- Widgets made before `KisStudioGlass::installMenuGlass()` were polished without it: anything new must be polished before its native window is created.
- A stroke's step reaches the undo stack a moment after the image goes idle: wait a turn of the event loop before deciding a stroke was cancelled.
- A drag owned by the widget it starts from dies with it: parent drags to `qApp` and delete them after `exec()`.
- A drag must check `event->buttons()` on every move: a release in another window never arrives.
- A tool's `updateSettingsViews()` must block its widgets' signals while setting them, or stale neighbours get written back.
- Windows headers define `near` and `far` as macros: don't use them as names.
- A widget's Leave event also arrives while its children are being deleted: hover handlers touching children must not run then (`HoverWatch` defers).
- Krita's stroke preview (`KisPresetLivePreviewView`) paints over its palette's window color: give it a transparent Window and Base to show it on glass.
- A lambda taking a `const QString &` into a list must not refresh that list before it is done: take such ids by value.
- Classes without `Q_OBJECT` (`KisStudioPanelColumn`) can't be found with `findChildren<T *>()`, which returns every widget: use `dynamic_cast` (`columnsBeside()`).
- A column sized by hand needs `QLayout::SetNoConstraint`, or its layout keeps an old minimum size.
- `setParent` hides a widget: read its visibility first and restore it.
- A view in fit mode refits whenever panel insets change: the canvas controller refits only while panels settle in (2 s from the first insets).
- A panel shown inside a hidden group gets no Show event: the stack watches ShowToParent and HideToParent (`shownChanged`).
- A fixed-height widget with no layout has no size hint (-1): read `minimumHeight()`.
- A hidden QDockWidget title bar still keeps its room: give it no height (`PanelGrip::setAlone`).
- A widget's drag filter takes events only from its own children, or presses passed through from elsewhere start drags.
- Blend ops must keep channels switched off (channel locks) and clear them where nothing was painted (`KoRgbU8ColorSpaceTester`).
- Writing a layer's or the selection's device outside a `KisTransaction` while under undo corrupts the history (`KisMementoManager::getMemento`).
- With `-fmath-errno`, `std::sqrt` in a loop doesn't vectorize; `std::sqrt(std::fmax(x, 0.0f))` does.
- `QWidget::mapTo` crashes unless the target is an ancestor: map through `mapToGlobal`/`mapFromGlobal`.
- Segoe UI Variable has no italic: `KisModernStyle::polish` gives italic text Segoe UI (`italicFace`); italic set after polishing isn't caught.
- An item view's hover look needs `WA_Hover` on its viewport (`KisResourceItemListView`).
- Krita's slider boxes (`kis_slider_spin_box_p.h`) veil themselves while typing; ending the typing must redraw what's under them. Check fields after typing, clicking again and clicking away.
- Anything moving over the canvas repaints every panel each frame: keep row painting cheap (a stroked `QPainterPath` halo on brush names cost 22 ms a frame).
- A group's place is a share of the room `spanY` gives it: anything that writes a place must use that same room.
- Caches of pictures need a bound by bytes, not only count; kept files stay small (logs restart past 1 MB, stale entries dropped).
- Measure before optimizing: the composite ops' cost was the color conversion, not the mixing math. A benchmark from `build-tests` (`KoCompositeOpsBenchmark`) loads color plugins from whatever folders it finds, the installed Skissa too: copy the .exe into `env\_install\bin` to run it against the dev install, with `QT_FORCE_STDERR_LOGGING=1` to see its output.
- A fresh profile's first start builds Krita's resource database (`KisResourceCacheDb`). It took 24 s: `updateMetaDataForId` committed the caller's transaction, so every later statement synced to disk on its own. A helper commits only a transaction it began. Measure the first start by deleting the apart profile's `resourcecache.sqlite` (kept aside and put back) and sampling (`KRITA_DEV_SAMPLE`).
- A program unpacked fresh starts slowly once (12–24 s here) while Windows scans its files: time starts on fresh copies, and know a second start is warm.
- Time a stroke's whole cycle, not only its work: liquify's updates took 10 ms but came every 100–200 ms, the rest spent copying and rescaling the point grid between them (found by timing each job in `KisUpdateJobItem::run`).
- Eraser mode is the brush's in Krita (its `EraserMode`): anything that switches the brush unasked (layers remembering their brush) must keep the eraser as it was, or the eraser key seems to do nothing. Hold-to-revert (`KisStudioHoldKeys`) takes back such switches only after a stroke: a tablet pad's button press can last past the hold time.
- Anything holding text is sized from the font (`fontMetrics()`), not a fixed number, with the old number as the least: at a large interface font, fixed rows, labels and badges clipped or overlapped. Test sizes with the apart profile's `custom_font_size`, `custom_system_font` and `use_custom_system_font` at the top of its kritarc and in each theme of `[StudioThemes] List`. The top bar shortens the brush name and then takes a row of its own under the window's buttons (`TopPill::squeezedTo`).
- The full test run (`tests.ps1`) puts Windows crash dialogs on the owner's screen from Krita's tests that crash (`kis_view_signals_test`, `kis_clipboard_test`): while the owner is at the PC, run only the tests that cover the change (`ctest -R`).
- The canvas in the Studio never emits `QOpenGLWidget::frameSwapped`, and a queued `QMetaObject::invokeMethod` lambda from `paintGL` didn't run either: mark "after this frame" with `QTimer::singleShot(0, …)`.
- An Enter posted by `devinput.ps1` right after a `drag` is lost; move the pointer first (a real pen always does).
- Windows 11 runs the timers of a program whose window it counts as hidden (behind others, as the dev build often is) at its 15.6 ms tick, Qt's short precise ones too: the canvas's 2 ms frame timer held dabs back up to 16 ms. It also runs such a program's threads at efficiency speed (EcoQoS): effects behind another window took three times as long, and every timing of the dev build behind the Claude app was that slow. Skissa opts out of both at start (`PROCESS_POWER_THROTTLING_IGNORE_TIMER_RESOLUTION` and `_EXECUTION_SPEED`, `KisApplication`). Suspect timer resolution when a wait spreads evenly over 0–16 ms; suspect EcoQoS when work in the app is far slower than the same work in a harness.
- A native event filter also sees messages Windows sends in the middle of other work (a title being set): only the event loop's own call passes no `result`.
- Never type into Find (or any field) to drive the dev build: if it hasn't opened yet, the letters land on the canvas as tool keys and change the owner's tool, eraser and colors. Open things with `action.ps1`; `devinput key` takes Qt keys and modifiers (Return is `0x01000004`, Ctrl `0x04000000`).
- A copy of a layer (`new KisPaintDevice(*dev)`) keeps the image's default bounds, so while the image shows a coarse preview it reads its own empty lower level: panels' pictures came out blank. Copy with `KisEffectPanels::fullSizeCopy`.
- `KisCanvas2::refetchDataFromImage()` takes the image's lock and waits for running strokes (Krita's modal "Waiting…"): to redraw the canvas while an effect previews, call its `startUpdateCanvasProjection` slot.
- `std::vector<T> a(n), b(size_t(m));` declares `b` as a function (the most vexing parse): write `static_cast<size_t>(m)` or braces.
- Measure where time goes before trusting a reading of the code: an effect's second opening, CPU per thread (`threads.ps1`) and the sampler's main thread together. Hovering the canvas at 360 Hz costs about 1 ms of main thread and as much in the driver a frame; that is showing frames, not waste.
- The frame log (`KisUpdatePacer::log`) writes one file from the window's thread: from an image worker thread it corrupted the heap (0xc0000374) within seconds. Log from a worker through `QMetaObject::invokeMethod(qApp, …, Qt::QueuedConnection)`, with the values read before.
- A widget made a child of the canvas takes the canvas's cursor, which is hidden (the canvas draws the brush outline): give it its own (`setCursor(Qt::ArrowCursor)`), or the pointer vanishes over it.
