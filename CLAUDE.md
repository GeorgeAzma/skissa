# Skissa: how we build it

This is the working guide for this fork. Read it before changing anything; it explains what we value, how the main systems fit together and how to work with the owner. **It is a living document: when you learn something that a future agent needs (a principle the owner states, a mistake worth not repeating, a system you added), add it here in the right section, briefly, and remove what has become false.**

## What this is

Skissa (Swedish: "to sketch") is a personal fork of [Krita](https://invent.kde.org/graphics/krita) (upstream: KDE). Branch `main`, pushed to the `skissa` remote's `main`. The owner is a digital artist who paints in Krita daily and wants it to feel as obvious and visual as the tablet apps (Procreate-like) without losing Krita's power. The fork rebuilds the interface ("Studio"); the painting engine, file formats and resources stay Krita's.

The owner works fast and reviews results afterwards. They mostly talk about how things look and feel, not about code.

## How to work with the owner

- **Automate; don't ask what you can decide.** Build, install, relaunch, test and commit without checking in. Ask only for decisions that are really theirs (design direction they reserved, outward-facing actions like pushing or publishing).
- **"Give me suggestions" means text only.** Don't implement suggestions until they say "implement", "do it", or pick numbers. When they pick, do exactly those.
- **Finish every task in a message**, including ones sent mid-turn. Keep a list.
- **Verify visually.** Launch the dev build and capture the window (see Dev workflow) before saying a UI change works. Say plainly what you could not verify.
- **Report like a person:** what changed, what they'll notice, what's left. Short.
- When the owner says something feels wrong, believe it and find the cause; don't argue from the code.

## Design principles

These come from the owner's feedback over many sessions. They decide most questions.

1. **The canvas is the product.** Chrome is a cost. Everything else appears where and when it's needed and gets out of the way.
2. **Needing explanation is a design problem.** Before adding a hint or tooltip, make the control self-evident: a picture, a live preview, direct manipulation, a better default, or removing the option.
3. **No grey helper text. Ever.** No info icons, no descriptions under settings, no "click to…" labels. A short tooltip is the fallback. Grey (secondary ink) is for quiet *values or state*, never for instructions.
4. **Sentence case.** "Open recent", not "Open Recent". Krita's Title Case commands, menus and panel names are shown in sentence case in English (`KisSentenceCase`, applied where actions, menus and panels get their text; names and acronyms keep their capitals); translations are untouched. Commands Krita names in code get it as a menu receives them (`KisStudioLayout::tidyCommand`, which also keeps classic-only items hidden when Krita makes them again); the captions of Krita's forms (checkboxes, radio and push buttons, group titles, tabs, labels beside a field or ending in a colon) get it, without the colon, when the style polishes them (`KisModernStyle::polish`); option names in `KisPaintOpOption::label`; widget tooltips in `KisStudioTips`. Items the user named (files, layers, brushes) never go through it.
5. **Shortest clear text.** "Layer 5", not "Paint Layer 5". Drop type names, restated context and "Click to". Most controls need no tooltip: if the name says it ("Glass blur", "Last image", "Eraser keeps its own size"), leave it out; don't explain choices one by one either. When one is needed, it's one line an artist would say, telling what the name can't ("Huge brushes paint slowly", "Nearest is best for pixel art", "Check your values"): no restating the name, no "X, but Y" or "…, so …" constructions, no "e.g.". A short name before ": " shows in bold above the rest (`leadOf` in `KisStudioTips`; "Alpha lock: paints only on what's already painted"). A button whose name says what it does gets just the name ("New theme").
6. **Direct manipulation over forms.** Drag a value on its own label or row (layer opacity, brush settings rows, scrubbers). Handles on the canvas instead of number fields (symmetry). Typing is a double-click away, in place: the number itself becomes editable, no box (`widgets/KisStudioInlineEdit`). **Right-click resets a value to its default.** Shift drags finer.
7. **Show, don't name.** Live previews on the real image (effects on canvas, blend modes as thumbnails of the actual picture, brush tooltips with strokes), curves as little drawings, themes as swatches.
8. **Fewer options, better defaults.** Remove settings nobody should need (they were removed: contrast, swap, animation cache, AVX toggles, undo-to-disk…). Merge duplicates. Put an option where its subject is (the eraser's own size is on the Size page) and also in Settings so it can be found.
9. **Organized by intent, found by search.** Group by what the artist wants ("Blur", "Darken"), not by implementation. Everything is reachable with Find (Ctrl+K), including words from other apps.
10. **Perceptual controls.** Brush size moves by ratios (log); opacity stays linear.
11. **Stable places, personal content.** Primary controls don't move. Customizing uses the same gestures as using (drag, right-click) and always has a reset.
12. **One undo.** Ctrl+Z also undoes settings changes, interleaved with document steps by time.
13. **Stay Krita underneath.** Files and presets the fork writes must open in upstream Krita and the other way round. Never change a preset just by loading it. Keep upstream code paths intact so merges from upstream stay easy.

## Look and feel

All tokens live in `libs/widgetutils/KisModernStyle.h`. Use them; don't invent numbers.

- **Spacing:** `hairline` 2, `space1` 4, `space2` 8, `space3` 12, `space4` 16. Nothing else.
- **Corners:** squircle corners everywhere (`KisModernStyle::squircle`, quarters of |x|⁴+|y|⁴=1). Radii by size: `cornerRadius` 5 (controls), `tileRadius` 8, `cardRadius` 10, `panelRadius` 14. Checkboxes are full squircles (`fullSquircleRadius`). Radio buttons stay circles.
- **Motion:** one curve, an exponential ease-out (`motionCurve()`), and three durations: `enterDuration` 180 ms, `exitDuration` 120 ms, `changeDuration` 160 ms.
- **Ink:** text in the palette's text color; quiet values in `secondaryInk()`; fills and tracks as text color at low alpha (works on any theme and on glass). The accent is optional (themes can have none).
- **Glass:** panels, popups and dialogs are frosted glass over the canvas, with edge refraction and a thin Fresnel edge light. See the Glass system below before touching any panel painting.
- **Icons:** `krita/pics/svg/{dark,light}_studio_*.svg`, generated by `krita/pics/svg/make_studio_icons.py` (24 px grid, round strokes; a switch that is on is drawn solid). The app icon is a bare pencil S, white with a soft shadow on dark themes and ink on light ones (`light_`/`dark_krita-branding.svgz`: Krita names icons by their own color, so `dark_` is the ink one); the window and taskbar icon follows Windows' own light/dark setting live (`taskbarIcon()` in `KisApplication`), and places Windows takes from the .exe (file browser, Start, shortcuts) get the white S, whose shadow grows stronger at small sizes so it reads on light backgrounds too; Qt's SVG has no blur, so the shadow is a small PNG inside the SVG. All of it comes from `krita/pics/branding/make_icon.py`: the .kra/.krz file icons and in-app glyphs, the macOS `.icon` bundles and `.icns`, Android's launcher icons and the Windows Store tiles (whose taskbar S follows the light or dark taskbar); the splash wordmark is `krita/data/splash/banner.svg`.

## Main systems

A map, so you know where things are and how they think. Files are in `libs/ui/` unless noted.

- **Studio layout** (`KisStudioLayout`): the whole shell. Left rail (tools, color chip), right rail (panels as flyouts that pin), top bar = the current tool's context (tool chip with the brush name, the tool's own options, size/opacity, the brush and blend mode), then its buttons (`KisStudioBarButtons`: symmetry, shapes, eraser, alpha lock, reload by default; any command can be added, `StudioBarItems`; the paintop box's own buttons are hidden while Studio is on). Canvas-only mode brings the bars back while the pointer is at a canvas edge (`peek`). The classic layout is the `view_studio_layout` toggle.
  - The tool rail, the top bar and each panel column go anywhere by their grip (a tap tucks them away). Each place is kept as shares of the room it can move in (`shareOf`, `StudioLayout*Spot`), so edges, corners and the middle catch it (20 px, the middle 10; more catches too eagerly) and it stays there as the window changes size; tucked, it is placed as if open, so its grip stays under the pointer. A column against its edge is docked (the canvas makes room); elsewhere it floats. Groups keep off the tool rail (`railRectProperty`) and off each other: one overlapping moves to the nearest place clear of all of them (beside, above, below, or a corner two make), the rail always staying; the group moved last makes way (`clearOfOthers`, `settledCount`); a dragged group already makes way while held, so it shows where it will stay. What the pointer doesn't move glides there (making way, catching onto a group, parting; `glideTo`, the motion curve): the owner wants to see panels move, not jump. Below the rail a group can reach the edge. A group is one glass pill of lanes side by side, each a stack of panels (`StudioLayoutPanelLanes`, each lane's width in `<width key>Lanes`). A group dragged by its grip within 16 px of another's side (along 40 px of it) shows the drop indicator there and, dropped, joins it as lanes beside its own; a single lane dropped at another's top or bottom joins that lane's stack (`joinAt`, `joinGroups`; the column with the panel buttons, or the one across, is the one kept). A panel dropped near a group's left or right edge starts a lane there. The line between two lanes resizes them on a drag and takes them apart on a click (`LaneDivider`, `separateLanes`), as a tap on the line between two stacked panels does for the panels below it (`separateBelow`): what is left keeps its place and the rest becomes a group of its own beside it. Joined groups were tried as separate pills kept in step (a graph of joins): tucking, panels moving between groups and the panel buttons' column each broke them; one widget can't come apart. A group that makes way when placed last keeps the place it went to (so the next start agrees). A group's grip folds its panels on a tap (all, or unfolds them when all are folded, `foldGroup`); the only panel of a group has no title bar of its own, except folded, when it shows the name. A group keeps its top as it grows or folds (against the bottom, its bottom): its spot is kept with the height it was taken at (`StudioLayout…Spot` = "across,down,height", `m_refHeight`). The top bar along the top or the bottom pushes the view and what is placed there (`studioCanvasBottomInset`). Its grip moves the bar, not the window. The window's handle stays in the top left corner when the bar goes elsewhere, and the rail keeps its gap under it (`handleBottomProperty`).
- **Zoom pill** (`KisStudioCanvasHud`): zoom (a click goes to 100%, from 100% to fit), value view, mirror, rotation and the modes that are on, in the canvas's corner; it goes anywhere free by a drag on it or its buttons (`StudioLayoutViewPillSpot`, `KisStudioLayout::spotShare`): its room is the whole canvas area, and it keeps off the bars, the tool rail and the panel groups the least it takes (where they are going, `studioTarget`), while dragged too. It holds buttons of its own, a second `KisStudioBarButtons` (`ViewPill`, `StudioViewPillItems`, none by default; buttons drag between it and the top bar); its right click adds them or hides it (`StudioViewPill`, in Settings' Zoom card, so Ctrl+Z or Settings brings it back).
- **Panel columns** (`KisStudioPanelColumn`, `PanelStack` in `KisStudioLayout.cpp`): pinned panels stack in groups, each a glass pill of its own: group 0 is the column with the panel buttons, 1 the one across the canvas (`StudioLayoutFarPanels`, for panels dropped near that edge), and from 2 on floating groups, made by dropping a panel's grip anywhere else on the canvas (`newPanelGroup`, `StudioLayoutPanelGroups`, `StudioLayoutPanelGroup<n>Spot/Width/Side`); they move by their grip like the other pills, and one left with no panels goes. A panel keeps its height: a panel that scrolls is fitted to its contents (160–360 px) the first time it is laid out and keeps that (`settled`), so a growing list (layers) scrolls instead of pushing the panels below it down; the line under each panel (the last one too) resizes it (`StudioLayoutPanelSizes`; right-click fits it again). When a group doesn't fit the window, its panels give up room down to their minimum. Krita's resource lists are kept as lists in a column (`keepUpright`), since short ones turn into a strip of tiles. A resource's right click lists every tag, its own first with ✕, the others with +, toggled in place with the menu staying open, and a new tag typed at the end (`resourcewidgets/KisResourceTagMenu`). Over a resource list: the tag (its list as wide as the longest tag, `KisTagChooserWidget`) and a magnifier that opens into the search while it is used (`KisTagFilterWidget`; Esc or leaving it empty folds it).
- **Start page** (`KisStudioStartPage`): with no image open, the Studio shows its own page in place of Krita's welcome page (kept aside, put back on leaving the Studio). Over the last image, blurred and veiled in the window color (fixed as the page scrolls), a pane holds the new images as tiles drawn to one scale (the size made last, screen, square, A4, 4K, portrait, the clipboard's image), Custom, which opens a panel under the tiles (`CustomImage`): the new image as a sheet pulled by its corner (`SizeStage`: a press puts the corner there, a side pulls one way) among the other sizes drawn as named outlines at the same scale from the same corner, zooming to fit after a drag; the corner catches lightly (6 px) on the other sizes' corners and the usual ratios (4 px), Shift drags free; beside it the numbers (`SizeNumbers`, dragged or typed in px, cm, mm, in), its shape and its size apart: shape chips (1:1, 4:3, 3:2, 16:9, A paper) that hold while dragging (the lit one again frees it; held, widths step so the height is whole) and ↻ to turn, then size chips by the long side (`NewImage::steps`: HD, 2K, 4K, 8K, or A5 to A2 at the resolution, those that fit), so any shape at any size is two clicks (8K 16:9, A3); with a shape held the sheet's outlines are its sizes and it catches on them, free they are the tiles' sizes; then resolution (only how big it prints; lands on the usual dpi, `roundDpi`) and color (model, depth, profile) as rows, paper colors and Make; what is made is the next one's start. Every new image has one layer, and there are no rows for layers or how the paper is made: the owner wants no controls past those. Catching from far off felt clumsy to the owner, none at all made aiming hard. Krita's dialog isn't reached from here (the owner wants no glued-on Krita parts); the Clipboard tile is Krita's Paste into New Image. And Open. Below, the last image large (Continue), then the others in rows that keep their shapes under Today, This week and Earlier (right-click: Forget). Typing filters by name, the arrows and Enter pick (the gallery takes the keys before the window's shortcuts), files dropped anywhere open. Pictures are read on two threads from the files themselves (`Pictures`; a .kra's merged image), since Krita's recent thumbnails are small squares. A size tile makes the image at once with the last image's color, background and layers. At the foot, after the gallery, three quiet links (`FootLink`): Support Krita (a small red heart, Krita's donation page), Skissa (the homepage) and Report a problem (its issues); never a banner or a popup. The desktop isn't shown behind it: that needs a see-through window, which the OpenGL window can't become only for the start page. It is also Home: a click on the S in the window's corner (`WindowHandle`, no longer a Windows caption: a drag moves the window by `startSystemMove`, a double click maximizes) or Find's Home shows it over the open images (`KisStudioLayout::showHome`, Krita's welcome page index); Esc, the S again or an artwork that is open goes back to it (shown, not opened twice); the zoom pill follows the page stack. An unsaved image isn't in the gallery: Esc is the way back to it.
- **Tools** (`KisStudioToolRail`, `KisStudioToolStrip`): 34 tools in 9 slots (Paint, Blend, Erase, Select, Transform, Fill, Shape, Text, Guides; Blend and Erase are the brush tool too, `toolSlots()`). Slots remember their variant; the brush in use decides whether Paint or Blend is lit. Inline tool options live in the strip, found in the tool's option widget by object name (inside `KisOptionCollectionWidget`s by the wrapper's `"id"` property, `withId`) and mirrored: selection modes with Grow and Soft (scrubbers that change the selection there is while dragged, one undo step per drag, `KisStudioSelectionAdjust`; Soft is a real gaussian, since Krita's feather is cut at 1σ and leaves a box), Move's layer under the pointer or current, Crop's shapes (Free, 1:1, 4:3, 16:9, the image's own) and ✓, the fill's threshold, a shape's fill and outline as menu pictures, gradient shapes. Connections to the option widgets need a context that dies with the strip's buttons.
  - Guides (`addGuides`, `plugins/assistants/Assistants`): Krita's twelve assistant types as four kinds, Line, Perspective, Ellipse, Curve, each a picture whose click makes the way it was last used (`[StudioGuides]`) and, when in use, lists its ways; the chosen guide's switches (verticals, only in an area) while it has them, the eye, and ⋯ (color, open, save, delete all). The box beside each guide keeps only its move grip; Snap, Lock, Duplicate and Delete are on the guide's right click (`KisAssistantToolMenu.cc`, `popupActionsMenu`). Handles are white with a dark ring. A brush tool's bar shows a magnet (Snap to guides) while the image has guides. Captures don't show guides (QPainter decorations): test through what they change.
- **Picking layers** (`input/kis_select_layer_action`): every click picks (a double click counts), on release; the top layer already active passes the click to the next one down; a drag of 8 px moves the pressed-on layer (`MoveStrokeStrategy`).
- **Make brush** (`KisStudioMakeBrush`, the selection's menu and Find): the selection's visible pixels become a picture tip, an even paper color around them made see-through (color to alpha), cropped, at most 1024 px; gray ones a mask in the brush's color, colored ones a stamp. Saved in the brush panel's tag when it is the user's, picked (the brush tool first), the quick editor on its tip.
- **Mixing** (`libs/pigment/compositeops/KoCompositeOpMix.h`, `KisStudioMixing`): a brush's paint mixes in RGB as Krita does, evenly (OKLab) or as pigment (Mixbox's shape without its table, its 120 numbers fitted to Mixbox's mixtures in `C:\code\krita-deps\pigments-lab`, `pigment.py`: four paints' amounts by a closed form, read from a grid of it made at first use, and a cubic Bézier tetrahedron back to the color; what the paints miss is carried along, so every color comes back exactly, and a mixture past sRGB is clipped per channel as Mixbox's are (shortening what the paints miss instead turned blue and white azure); light past sRGB mixes linearly), the brush setting `SkissaMixing`, chosen as three tiles in the quick editor's Color tab and under the sheet's blend mode. Blend ops `skissa_mix_{oklab,pigment}_{over,copy}` in the RGB color spaces (only `skissa_mix_pigment_over` is in the registry, as the layer blend mode Pigment in the Mix group, `KoMixing::layerMode`: a layer mixes into the layers under it by its coverage; brush blend lists leave it out, `KisCompositeOpComboBox::setForBrush`, `isLayerOnly`, since a brush mixes by its own setting; upstream Krita reads the unknown mode as Normal), converting each row to linear sRGB through the image's own profile (`KoCompositeOpInLinear`, which keeps channel locks as Krita's blends do), so sRGB and linear images mix alike; the stroke takes them for a Normal blend (`KisResourcesSnapshot`), smudging for its smear and its dabs (`mixedCompositeOp`). `resetSettings` keeps the setting, which no option widget writes. Upstream Krita ignores it.
- **OKLCH blend modes** (`compositeops/KoCompositeOpOklch.h`): Hue, Chroma, Color and Lightness as Krita has them in HSV, HSL and HSY, in OKLCH (`skissa_oklch_*`, the OKLCH group after HSV, `KoOklch::addTo`), on the same linear rows; a result outside sRGB keeps its lightness and hue and gives up chroma, and it is laid over what is under it as Krita's blends composite. Added with the mixing ops (`KoCompositeOpMix::all`). Upstream Krita reads them as Normal.
- **Find** (`KisStudioFind`): one index of items with keys (`tool:…`, `effect:…`, `brush:…`, settings, commands with their classic menu path). Ranking: prefix, word start, initials, all-words, then fuzzy; frecency from usage; aliases from other apps. Right-click or long-press any button opens its card (`KisStudioItemCard`): shortcut as a key cap you can re-record, variants, pin/remove. Tooltips show a button's shortcut after its name (`KisStudioTips::install`).
- **Settings** (`KisSettingsRegistry` + `KisStudioSettings`):
  - The registry is the single source of truth for every setting: id, default, how it's read and written, and flags (`Restart`, `Machine`, `Fork`, `NewViews`). Tooltips live in `explanations()`.
  - `forgetRetired()` is a versioned, one-time migration that clears settings the fork removed. Bump its version and keep it idempotent.
  - The registry also keeps the change history behind settings undo (`KisSettingsUndo` hooks the document undo stack).
  - A write made while another setting is being written (its `written` hook) joins that step, and `setValues()` makes several writes one step, so one Ctrl+Z undoes a theme preset with the theme switch it caused. Write settings through the registry, not `KConfigGroup`, or they fall out of undo.
  - A `KisConfig(false)` rewrites the whole kritarc when it changed something. The fork's frequent writes that aren't settings (a brush per slot, panel places, Find's usage, glass drags) go through `KisSettingsRegistry::writeLater`, saved once after the burst. Krita's own immediate writes stay: its crash detection relies on them.
  - The panel is cards (built with `Builder`: `toggle`, `number`, `choice`, `color`, `row`…), user sections, a Quick section, a Changed filter, a search box and an Undo for changes since it opened.
  - A setting that needs a restart gets a quiet refresh mark that lights up once changed, plus a Restart button. Never write "After a restart" in text.
  - `KisSettingsTransfer` copies settings from a regular Krita (Take Krita's settings), and its own brushes, presets, patterns, palettes and bundles into this one's resource folder (Take Krita's brushes; files already here are kept, and they load at the next start). Krita's own files are never written. Export also carries what the user arranged that isn't a setting ("arrangement": kritarc keys by `arrangedKeys` prefix, whole `arrangedGroups` such as saved curves and smoothing per brush, and kritashortcutsrc's shortcuts); import replaces it as a whole after copying kritarc and kritashortcutsrc to `.before-import-<time>`, and it takes effect at the next start. Add a new kind of user arrangement to those lists, or export loses it.
- **Theme** (`KisStudioTheme`): a theme is a few params (lightness, tint, tint amount, accent) turned into a generated `.colors` scheme, plus the rest of the look: glass, the glow around the image and the interface font (`held()`). Themes are one list (`[StudioThemes] List`, JSON, and `Current`, both registry settings so every change is one undo step); the shipped ones (Dark, Darker, Night, Moss, Light, Paper, Sky, Blossom) are kept like the user's, editable, renamed and deleted alike, with Reset and Restore deleted themes to get them back. The theme in use is what the settings edit: a held setting written goes into it (`remember`, chained onto those settings' `written` in the registry). The picker (`ThemePicker` in `KisStudioSettings.cpp`) puts the dark ones in rows above the light ones (four across, so the shipped eight are two rows); the + beside the card's ⋯ copies the one in use (a + tile made a third row); double-click renames in place, right-click for Reset and Delete. The first run keeps the look in use with the shipped theme of its colors, or as a theme of its own ("Mine", `settle()`). The generated scheme is "Skissa"; the shipped ones are "Skissa Dark/Light". `remake()` renames themes stored under the old placeholder name. Links and focus lines use the accent's hue at a readable lightness.
- **Glass** (`KisStudioGlass`, `opengl/KisOpenGLGlass`):
  - Panels over the canvas are painted *by the canvas* (GL blur/refraction behind them), and the widget paints only its content.
  - A panel is see-through only after a canvas frame has drawn all of it (`Panels::drewOver`); until then it paints solid.
  - Translucent popup windows must never have fully clear pixels: Windows passes the pointer through those to the canvas, which hides the cursor. The style fills them with alpha 1.
  - Captures (`window->grab()`) re-render popups, so they never show first-frame glass bugs.
  - A panel's edge is after Apple's Liquid Glass as preyneyv's Shadertoy (wfGXzh) draws it (`glassSource`): a band along the rim (20 px, kept within 0.9 of the corner's reach, where the distance has no crease) shows what is behind from further in, by 1 − cos toward the edge to twice the band's width, each color by its own power (a little more for blue); nothing inside the band moves. The frost follows the glass's thickness, (1 − u⁴)(1 − v⁴) with u, v from −1 to 1 across the panel: clear at the edges, the full Blur in the middle; Blur 0 is pure refraction. The blur narrows by octaves through finer copies of the frost (a half, a quarter, an eighth), the canvas softened and the canvas itself, three around the wanted blur mixed with quadratic B-spline weights (`frostAt`). At the very edge light gathers into a hairline (one widget pixel with a hard inner edge; any falloff reads as a blurred band): what is seen there, brighter and more vivid, brightest facing the room's light (top left and bottom right), as strong as Rim light in Settings (`StudioGlassRimLight`, 0–200%). It only concentrates what is there (the lightness' odds doubled): a dark edge stays dim, a bright one never clips. Light added on the rim from the image beside it counted the image twice (the glow is already behind the glass) and was too strong next to a white page. The owner wants it thin, sharp and vibrant, like a specular from heavy refraction; a mirrored reflection band read as big and blurry. There are no refraction or clarity settings. Refraction over the whole panel (moving everything by a dome's slope) was tried: it magnifies the middle and loses the defined edge. Never blend a sharp image straight into a heavily blurred one (it reads as a double image).
  - The small blurred textures are read with a cubic B-spline (`softAt`): stretching them bilinearly leaves creases along their grid. Where they are half floats they keep values as they are (`KEPT_LINEAR`), so the spline is four filtered fetches; in eight bits they keep square roots and it takes sixteen.
  - Opacity is one smooth curve each over a dark and a bright canvas (`tintOverDark`, `tintOverBright`), reaching solid at 100%, where the tint also covers all of the chroma behind.
  - Each panel's blur is kept until something it reads changes: the canvas reports what it redrew (`canvasRedrawn()`), and only panels over that part blur again. The glow around the image is remade only for changes near its edge. Near the image the glow never falls below a dim neutral light (`ambientBacklight`), so a black or dark image keeps a visible edge; a bright edge's own glow is above it and looks as before. Bright light is compressed as eyes adapt (`ambientKnee`), so a white page glows little more than a mid-tone one. The glow is "Around the image" set to black; the color chosen for Color is kept apart (`StudioSurroundColor`), so switching back brings it back.
- **Effects on the canvas** (`KisStudioEffectOverlay`, `KisFilterManager::setInlineEditor`): any filter previews live on the layer with a small draggable glass panel. Enter keeps it, Esc drops it, the mask button keeps it editable. An effect opens with the settings it was last applied with (Krita's own "Last Used", `KisFilterManager::lastUsedConfiguration`); the panel's reset shows while they differ from the defaults. The picker's tiles use the same settings, rendered at the level of detail the thumbnail is to the image, so a 20 px blur looks as it will, each into a device of its own (in place, convolutions such as Emboss read pixels they had changed). The panel goes in the widest stretch of canvas at its height that floating groups, the rail and Settings leave (docked columns already make room). While it is open autosave waits (`autosaveHeld` on the document: its preview can't be saved), and opening an effect while the image is busy (a cancelled slow one finishing) waits quietly for it instead of Krita's modal "Waiting…".
- **Brush editor rows** (`kis_paintop_option`, `kis_paintop_settings_widget`, `kis_categorized_item_delegate`, `plugins/paintops/libpaintop`):
  - Each option's row shows its strength (`KisPaintOpOption::RowValue`): drag it, double-click to type, right-click for the brush's value from when it was picked (`rememberRowValues`). A value at 100% is hidden until hover. Locking an option is its lock icon.
  - The Size row is the brush diameter.
  - "The pen is on" means a sensor is ticked. There is no Enable Pen Settings checkbox (`rowCheckedLens`, `sensorsLens`). Opacity and Flow get a row checkbox for the pen. MyPaint rows don't, because MyPaint drops input curves when saved with the pen off.
  - Saved curves (`KisCurvePresetStrip`) are global, stored in `[SavedCurves]`, and renamed inline.
- **Quick brush editor** (`KisStudioBrushEditor`, `KisStudioPenPopup`, `plugins/paintops/libpaintop/KisBrushTipEditor`):
  - Opens from a click on the brush's chip on the top bar, its action, or a second click on the active Paint/Blend/Erase slot. Pressing the line anywhere makes the edge a curve that looks as it did and bends it there; right-click on a point removes it, elsewhere makes the tip hard. A tip softer one way than the other keeps the difference; there is no control to set it apart. Handles are white with a dark ring (softness dark with a light ring) and every line is drawn dark under light, so nothing disappears on a light dab or a dark one. Angle selectors have no flip buttons.

A smoothing change paints it again from the pen's own path (recorded before smoothing) through the smoothing as now set; the stabilizer is replayed by its millisecond samples, close to but not exactly as live. Only for a stroke of that brush, only while its step is the newest with nothing undone after it.

Polygons fit a line to the middle of each side and put corners where they meet (rounded corners and overshoots still snap); the stroke must go round once without crossing itself and turn at each corner. ## Dev workflow (Windows)

The build environment is outside the repo, in `C:\code\krita-deps`: llvm-mingw, KDE's prebuilt Qt5 deps in `env\_install`, the build dir `build`, helper scripts in `devtools`, and in its root `run-krita.bat`, `profile.py`, `baseline-tests.bat` and `known-failing-tests.txt`.

- **The fork's own files in `libs/ui` are listed in `libs/ui/skissa.cmake`**, not in kritaui's list: they build as their own part of kritaui, so editing one rebuilds in ~5 s instead of ~14 s (Qt's moc otherwise re-checks every kritaui header). Add new `libs/ui` files there. A form header (`ui_*.h`) they include goes in its `kritaui_skissa_forms` list.
- **One command:** `devtools\dev.ps1` builds, closes the dev Krita and waits for it, installs and launches (~10–20 s). Flags: `-NoBuild`, `-NoLaunch`. Build errors are matched case-sensitively; cmake's Python `ModuleNotFoundError` lines are harmless.
- **Always run the dev build through `run-krita.bat`** / `launchdev.ps1` (hidden console). It sets `KRITA_DEV_PROFILE=1` (Qt test mode), so settings and resources live in `%LOCALAPPDATA%\qttest` and `%APPDATA%\qttest`, with a separate single-instance key. **Never touch the owner's real Krita profile** (`%LOCALAPPDATA%\kritarc`, `%APPDATA%\krita`).
- **Driving the app:** the dev build listens for posted window messages (`krita/KisDevHooks.cpp`): `KritaDevCapture` (renders its own windows to a PNG; no screen capture, ever), `KritaDevMouse`, `KritaDevKey`, `KritaDevTree`, `KritaDevExport`, `KritaDevShortcuts`, `KritaDevColorDrop`. Helpers: `devinput.ps1` (move, click, rclick, line, type, key, capture), `pen.ps1` (a pen stroke whose pressure swells and fades; KritaDevMouse actions 12–14 carry the pressure), `colordrop.ps1` (a color over the canvas, dropped, left; auto flats; recolor: a real drag can't be faked), `tree.ps1`, `kritawin.ps1`.
  - Captures miss QPainter-only canvas decorations; GL-drawn tool outlines show.
  - Synthetic mouse moves don't move the OS cursor: use the event's `globalPos`, not `QCursor::pos()`.
  - Inside popups, Qt can hand `QContextMenuEvent::pos()` in window coordinates: map from `globalPos()`.
- **The shell sees a stale copy of `%LOCALAPPDATA%`** (the desktop app is an MSIX package). To read or edit the real dev `kritarc`, copy it with a WMI-launched process (`Invoke-CimMethod Win32_Process Create`), and edit it only while the dev Krita is closed.
- **Back up the dev profile before a test writes to it,** and restore exactly what was there. The owner also works in the dev build; tests have overwritten their saved curves and theme before.
- **It's fine to close the dev Krita** (unsaved changes and all) to rebuild. Only kill processes whose path is under `C:\code\krita-deps`.
- **README clips:** `devtools\rec.py` (Python, Pillow) drives the app and captures frames; save them as animated WebP (sharper and smaller than GIF). A capture takes ~1 s, so clips are stop-motion with chosen frame times.
- **Startup:** `KRITA_DEV_SAMPLE=<file>` samples it, `profile.py <file> --timeline 250` shows where the time went (`--callers`/`--callees` follow a function). `QT_LOGGING_RULES=krita.performance.debug=true` prints Krita's own phase timings. Most of it is Krita's (the OpenGL probe ~0.9 s, mostly the driver starting; opening the image), not the fork's.
- `KRITA_DEV_UPDATES=<url>` points the updater at another feed (a JSON like GitHub's latest release) to test updating; run a release folder with `KRITA_DEV_PROFILE=1` and `KRITA_DEV_APART=1` so it stays out of the real profile.
- `KRITA_DEV_TOUR=<folder>` runs `krita/KisDevTour.cpp`, which photographs the whole UI. `KRITA_DEV_FRAMELOG` and `KRITA_DEV_SAMPLE` are for performance work.
- `KRITA_DEV_STALLS=<ms>` logs every stall of the main thread longer than that, with where it was, to `krita-stalls.log` in the profile folder (`krita/KisHangWatch.cpp`); with the tour it shows where the interface hitches.
- **Tests (the safety net):** `devtools\tests.ps1` builds Krita's unit tests in `build-tests` (a second build of the same source), runs them, runs the failures again one at a time (some only fail when run together), and reports any failure untouched Krita doesn't share. `known-failing-tests.txt` lists those Krita shares, checked against `build-upstream` (`baseline-tests.bat`, a worktree of the merged upstream commit). Run it after a merge from Krita and after changes to Krita's own code (libs/image, pigment, flake, file formats). The UI tour (`KRITA_DEV_TOUR`, above) is the crash sweep for the interface; `devtools\tour_index.py` and `tour_maps.py` turn its photographs into an index and maps.
- **The test image** is `C:\code\krita-deps\sunset.png` (the default in `launchdev.ps1`); `glass-test.jpg` is the Krita artwork.

## Updating from Krita

`origin` is Krita (KDE), `skissa` is the fork's own repo. Merge Krita in often (small merges are easy); never rebase the branch.

- **One step:** `devtools\update.ps1` runs `packaging/skissa-update.py`: fetch, merge (rerere on, so a conflict settled once is settled again the same way), the fork's translations refreshed and committed, build and install, start and capture. Exit 2 leaves the merge open with the files to settle: settle, commit, run it again. Check the capture, then push.
- **Keep Krita's files mergeable:**
  - Put new code in new files and call it from Krita's with a line or two.
  - Turn Krita's code off in the build (CMake), don't delete it: an unbuilt file stays as upstream has it and merges cleanly.
  - Don't append to Krita's lists or files when a file of the fork's own can hold it (`po-skissa/`, `libs/ui/skissa.cmake`).
- **Check a merge before doing it:** `git merge-tree --write-tree --name-only HEAD origin/master` lists the files that would conflict.
- **Skissa's own copies of Krita's files**, built in their place while Krita's stay exactly as upstream has them: the layer, palette and time-lapse panels (`plugins/dockers/skissa_*`, with Krita's other files of those panels taken from its folders) and Multibrush (`KisStudioMultiBrush`). Krita's fixes to the files copied don't arrive by merging: the update script lists Krita's commits that touched them (`KEPT` in `skissa-update.py`), to bring over by hand.
- **Where the fork still changes Krita's code most** (moving these behind a call or two is the next step for easier merges): `KisMainWindow.cpp`, `kis_tool_freehand_helper.cpp` (stroke recording, stabilizer pressure), the brush option widgets in `plugins/paintops/libpaintop` (texture, curve options), `kis_preset_chooser.cpp` (the brush list's rows), `kis_paintop_settings_widget.cpp` (row scrubbing), `KisOpenGLCanvasRenderer.cpp`, `kis_config.cc`, `kis_slider_spin_box_p.h`, `kis_cmb_composite.cc`, `kis_paintop_box.cc`, `KisTagChooserWidget.cpp`. About 40 of Krita's files only change "Krita" to "Skissa" in their text.

## Open questions and known issues

- **The app is named Skissa** everywhere it names itself. The exe stays `krita.exe` and the internal ids (`krita` component, `.kra`) stay, as they should. The splash art is Kiki, Krita's mascot (credited, CC BY-SA); art of the fork's own would separate it further.
- **The homepage is `github.com/GeorgeAzma/skissa`** (`KisProfile::homepage()`, `make-release.py`); change both if the repo moves.
- **The README says plainly that all the code is AI-written** and the ideas are the owner's; keep that true and visible. Its donate button goes to Krita.
- Taking Krita's brushes copies files, not Krita's tags (those are in its resource database), except what bundles carry.
- **Pre-5.0 brush engine paths were removed** (legacy smudge, spray center bias, hard flow). Old presets that used them paint slightly differently.
- **G'MIC-Qt isn't built** in `krita-deps`, and neither is the bridge plugin. The idea on the table is wrapping the useful G'MIC filters as native effects.
- **The owner asked to be reminded** of shader filters and custom blend modes written the same way (shader-like code).
- **Ideas the owner liked:** shader-based custom filters in the effect panel (Shadertoy-style GLSL; the sliders come from uniforms).
- **Performance left on the table** (each needs Qt or Krita's own code changed):
  - Krita's compressor delays on costly slots were set to one frame (`KisFrameRate::frameMs()`, 4–7 ms at high refresh): the transform tool's update, the selection outline, vector layer rendering, zoom, the canvas controller, the color selectors. A floor such as 30 ms for the costly ones would keep most of the smoothness for less work.
  - Seen in passing in Krita's code: `KisFilterManager::apply` waits on the GUI thread when no preview runs; `KisUpdateOutlineJob` redoes the whole selection's outline on every change; `KisToolUtils::findNodes` reads every layer; `KisPaintopBox::slotUpdateOptionsWidgetPopup` re-reads the whole editor for one setting.
  - The fork's own, small at today's sizes: the brush picker paints every stroke again on a color change while open; replaying a long stabilized stroke builds a sample per millisecond on the GUI thread; Find scores every entry per key.
- **A layer dragged off the panel onto the canvas is deleted** (undoable); an overshoot while reordering does it too. Keep, or delete only when dropped outside the window?
- **The layer menu's missing glass** wasn't seen happening; three likely causes were fixed. A screenshot would settle it if it shows again.
- **Ideas weighed and left:** handles to nudge a snapped shape (an editing state after every stroke), time-lapse trimming (the export's ffmpeg templates are saved settings that read every frame; trimming means changing them or copying frames), a theme taken from the image (a theme is a stable personal choice), a canvas flip gesture (not wanted). Lasso fill: Krita's Freehand Path brush already does it.

## Lessons (append, newest last)

- Check the dev profile's state before blaming code: a "wrong" value is often a setting (e.g. "Largest brush" capping the size display).
- A setting the fork stops showing must still be read correctly, or be migrated. Deleting a key upstream still reads is a bug.
- Count only deliberate input as "the user is working": pen hover sends moves all the time.
- When a feature writes test data into the profile, prefer the UI (with the panel's Undo) over editing files.
- Public text (README, release notes) is shown, not told: a clip or screenshot per feature, a line of words at most, plain first-person voice. Release notes are pictures and a line or two of plain facts (how to run it), almost no text; anything that sells reads as marketing to the owner. Bold lead-ins, feature lists and comparison tables read as machine-written to the owner.
- After a build, check the installed DLL's time: an install can silently keep the old one when the dev Krita was still running.
- Another session may be driving the dev Krita too (and may have started it with other variables, such as `KRITA_DEV_APART`). If a capture shows a fresh-looking profile, check the process's command line and parent before suspecting the code.
- Windows caches program icons by path: after the .exe's icon changes, Task Manager and Explorer can keep showing the old one until `ie4uinit.exe -show` refreshes the cache.
- Creating a `QOpenGLFramebufferObject` in the middle of a frame leaves bound the framebuffer Qt last knew of, not the one that was bound: the rest of the frame lands off screen. Create them through `KisOpenGLGlass`'s `texture()`, which keeps the binding. (This was the glass missing under a menu the first time it opened.)
- A fill run through `FillProcessingVisitor` changes the layer but not the canvas: add a `KisUpdateCommand` with its dirty rect to the same stroke, as the fill tool does.
- Fills that read the whole picture must not take earlier fills for lines: what counts as a line (for line width, for the layer that holds the lines) is dark ink, not "differs from the clicked color".
- Python one-liners in a bash heredoc turn `\n` inside C++ strings into real newlines: make escape-heavy edits with the Edit tool.
- PowerShell's `[int]` rounds (to even), it doesn't truncate: use `[math]::Floor` in test scripts. `Set-Content -Encoding utf8` writes a BOM, which CMake files can't take.
- In a fresh profile (`KRITA_DEV_APART`) the UI scale differs, so devinput coordinates are logical pixels there; in the dev profile they match the capture's pixels.
- Find's application filter opens its own card on any button's right click: a button with a card of its own sets the `ownContextMenu` property.
- Widgets made before `KisStudioGlass::installMenuGlass()` were polished without it (resource lists' item tooltips): the install pass converts those, and anything new must be polished before its native window is created.
- A long press arrives as a plain right click; `longPressAt` on `qApp` tells them apart.
- Ctrl+Z in a test also undoes settings changes (one undo), so undoing test strokes can undo a toggle made for the test.
- The UI tour (`KRITA_DEV_TOUR`) decides what is safe to press from a button's text, tooltip, object name and accessible name: a button with none of these (an icon-only button whose tooltip was removed) must still get a name, or the tour may press Close. Run it with `KRITA_DEV_APART=1` so it can't touch the dev profile.
- The owner uses the dev build between turns (pins, tweaks): back up the profile right before each test, not once per session, and capture before clicking by coordinates, since the bar may have moved.
- A stroke's step reaches the undo stack a moment after the image goes idle: wait a turn of the event loop before deciding a stroke was cancelled.
- A drag owned by the widget it starts from dies with it: anything rebuilt while the drag runs (a brush picked, a card refreshed) takes the QDrag along and Qt crashes. Parent drags to `qApp` and delete them after `exec()`.
- A tool's `updateSettingsViews()` must block its widgets' signals while it sets them: one set first writes its stale neighbours back into the options (the smoothing sliders, the combo's ranges).
- Anything that keeps the brush's option widget in step (`KisPaintopBox::useOptionWidget`) takes and gives back a use; one shared flag let one closing editor stop another, or pinned rows go stale.
- "Pen pressure doesn't work" can be the pen arriving as a mouse: The tablet driver can refuse WinTab to every program, upstream Krita included (seen with the owner's XP-Pen; why is not known yet). At start the app tries to open WinTab and uses Windows Ink for that session when it is refused (`KisWinTab::refused()`, `krita/KisWinTab.cpp`), without changing the saved setting. Test the app side with `pen.ps1`; for the real pen, log whether the canvas gets tablet or mouse presses.
- A console program started through WMI (`Win32_Process.Create`) hangs when Windows Terminal is the default console: Terminal takes the console and the program never runs. Start them detached (`Win32_ProcessStartup` with `CreateFlags = 8`, and `ShowWindow = 0`).
- A second Krita started with `KRITA_DEV_APART` hands itself to a running dev Krita and quits: close the dev Krita before the UI tour.
- Windows headers define `near` and `far` as macros: don't name variables or members so in files that include them.
- `Copy-Item` keeps a file's old modified time, so ninja won't rebuild a source copied back over a newer one: touch it.
- A widget's Leave event also arrives while its children are being deleted (a deleted child under the pointer): a hover handler that touches the row's children must not run then (`HoverWatch` defers its call).
- A first rebuild of the glass as one refraction-and-frost model went through several rounds, and the owner found every version worse than the two-part glass before it, so it went back; the glass as it is now (see Glass) came after, from a reference (preyneyv's Shadertoy). Before changing its look, get a reference image of the glass they want; don't iterate on numbers blind.
- Krita's stroke preview (`KisPresetLivePreviewView`) paints over its palette's window color: give it a transparent Window and Base (fork side) to show the stroke on glass.
- The glass shader links on the driver's threads (KHR_parallel_shader_compile, which ANGLE has): `Program::finish` checks without waiting and the panels paint solid until it is ready (the canvas looks again every 200 ms). Waiting on the link froze the window for 10+ s at start. Keep the shader small too: every call of a big GLSL function is inlined into the HLSL (the edge blur read once, not per color).
- Synthetic presses (`devinput.ps1`) go to the topmost window under the point, and a tooltip counts: hovering a spot long enough for its tooltip and then pressing there sends the press to the tooltip, so the popup closes as if pressed outside. Move and press without waiting, or move away first.
- `adjustSize()` sizes by `sizeHint()`, which leaves out chip rows that wrap (height for width): a column of the brush sheet came out short and its first box was squeezed under the next. The sheet's columns ask for their height at their width (`Column`).
- A lambda that takes a `const QString &` into a list must not change what refreshes that list before it is done with it: picking a pattern refreshed the pattern row, which cleared the ids the picked one referred into (a crash). Take such ids by value.
- `KisStudioShortcuts::allActions` once listed every action twice (the window's collection and the window's own actions hold the same ones): the Keys page counted each key as two commands and showed conflicts everywhere. Lists of actions joined from several places must be made unique, by name too: a window can hold two actions of one name (the Keys page shows one row and gives both the keys).
- `KisStudioPanelColumn` has no `Q_OBJECT`, so `findChildren<KisStudioPanelColumn *>()` returns every widget: reading a column's members from that list crashed. Find classes without a meta object with `dynamic_cast` (`columnsBeside()`).
- Moving a group off one obstacle at a time can land it on the next (the rail, then a group) and bounce: pick the nearest place clear of all of them at once.
- A column sized by hand must not let its layout set its minimum size (`QLayout::SetNoConstraint`): the minimum kept from when its panels showed kept the tucked column at full height.
- Moving a widget between stacks with `setParent` hides it: read its visibility first and set it back, or a panel handed from one lane to another disappears.
- A view in fit mode refits whenever the panels' insets change, which zoomed out the image the first time a panel was docked: the canvas controller refits only while its panels settle in (2 s from the first insets).
- A panel shown inside a hidden group (one with no other panel shown) gets no Show event, so its toggle never told the layout: the stack watches ShowToParent and HideToParent and asks for the columns again (`shownChanged`).
- A widget with a fixed height and no layout has no size hint (-1): the groups' dot strip made every floating group 15 px short. Read `minimumHeight()` for such widgets.
- The zoom pill watched the canvas area for its resizes and also took the mouse events that reached it: a press a panel group let through started dragging the pill. A widget's drag filter takes events only from its own children.
- A hidden QDockWidget title bar widget still keeps its room (an empty strip at the panels top): give it no height instead (`PanelGrip::setAlone`).
- Krita's unit tests (`build-tests`) load their plugins (color spaces, paintops) from the installed dev build (`env/_install/lib/kritaplugins`), not from `build-tests`: install the change (`dev.ps1 -NoLaunch`) before testing code in a plugin. Blend ops must keep channels that are switched off (the layer's channel locks) and clear them where nothing was painted, as `KoRgbU8ColorSpaceTester` checks. `TestKoZoomAction` fails by design (the fork's zoom steps).
- Writing a layer's or the selection's paint device outside a `KisTransaction` while it is under undo corrupts the history (see `KisMementoManager::getMemento`): a preview may not write the real device untracked.
- `QWidget::raise()` costs nothing when the widget is already on top, but two overlays that raise themselves on the same event swap places and repaint every time: overlays use `KisStudioLayout::keepAbove`, and raise only what is being dragged.
- With `-fmath-errno` (this build's default) a `std::sqrt` in a loop doesn't vectorize; `std::sqrt(std::fmax(x, 0.0f))` tells the compiler the argument isn't negative (the pigment mix got twice as fast from that and floats).
- Synthetic drags (`devinput.ps1 drag`) don't move the tip editor's value chips or the selection's Grow and Soft scrubbers: test those by hand, or through what they change.
- `TestCompositeOpInversion` takes about 520 s when the machine is busy, past ctest's 400 s timeout: a timeout there in `tests.ps1` isn't a failure; run it alone with `--timeout 900`.
- The owner's installed Krita (Program Files) may be running: anything that waits on or stops `krita.exe` must match the path under `C:\code\krita-deps`, not the name.
- Don't run the UI tour while the unit tests build or run: under that load it stalled in a Windows timer call and died with no stack. A tour step begun and never ended counts as a crash in later runs (only its picture): every early return in a step must `end()` it.
- Testing brush settings by painting: while the brush editor is open, each change repaints the last stroke with it (re-stroke), so a stroke painted before switching a mixing mode ends up in the next mode. Paint a throwaway dot before each switch.
- A drag must check `event->buttons()` on every move: a release that lands in another window (Alt-Tab, a popup) never arrives, and with mouse tracking on, hovering kept dragging (the tip editor, the effect overlay, panel groups).
- The release zip is made from the dev install, which is built with `HIDE_SAFE_ASSERTS` off: `kis_assert.cpp` keeps the "internal error" box to the dev profile and only logs it elsewhere.
- Two sessions building in `C:\code\krita-deps\build` at once break each other's CMake regeneration ("rebuilding 'build.ninja': subcommand failed"): build again.
- Killing a Krita that changed the test image leaves `.sunset.png-autosave.kra` beside it, and the next start waits on the recovery prompt (a tour then sits before its window shows): delete it after a kill.
- Pick a brush through `KisPaintopBox::resourceSelected`, as Krita's brush panel does: setting it only on the canvas resources (`setPaintOpPreset`) paints with it but leaves the box's settings widget, and so the quick editor and the brush sheet, on the last brush's engine.
- A process started from Skissa inherits its working folder, which is the program's bin folder when Skissa is started from a shortcut, and Windows won't rename a folder a process works in: anything that renames the program folder (the updater) must start its helpers elsewhere (`setWorkingDirectory`). Test updates with Skissa started from its bin folder.
- Every write to kritarc must end on disk: `KisSettingsRegistry::writeLater` or registry `setValue` schedule the sync, a `KisConfig(false)` syncs when it goes, but a raw `KConfigGroup::writeEntry` stays in memory until something else syncs, so a crash loses it: follow it with `KisSettingsRegistry::instance()->scheduleSync()`. The Keys page saves each edit 300 ms after it (`storeEdited`), not only when it is left. Restart flushes settings and starts the new copy only after this one has ended (a hidden `Wait-Process`), since a second copy starting first hands itself to the dying one.
- The UI tour's photos have artifacts of their own: popups are drawn in no particular order (a submenu can come out under its parent), a picker opened "at the pointer" opens where the real pointer is (synthetic clicks don't move it), glass dialogs are near-transparent PNGs (look at them over a dark ground), and closing an image the tour changed waits on a save prompt (no start page). Check a finding by hand before fixing it.
- `QWidget::mapTo` needs the target to be an ancestor and crashes otherwise: map between widgets of different parents through `mapToGlobal`/`mapFromGlobal`.
- The UI font, Segoe UI Variable, has no italic: Qt slants it and clips the letters. `KisModernStyle::polish` gives italic text Segoe UI's own (`italicFace`); text set italic after polishing isn't caught.
- An item view's hover look (`State_MouseOver`) needs `WA_Hover` on its viewport, which the style doesn't give item views: without it nothing is lit while hovering (resource lists set it, `KisResourceItemListView`). Synthetic moves (`devinput.ps1 move`) do hover then; test hover through them, not `QCursor::pos()`.
